# 4.2 求职指南

> 本章适合谁：准备求职 FDE 的读者
> 学完能掌握：简历 / 面试 / Offer 谈判 / 投递策略
> 预计阅读：15 min
> 版本：v1.0 / 2026-10-13

---

## 一、求职全流程

```
准备阶段（1-2 月）
  ↓
简历 + 项目（1-2 周）
  ↓
内推 / 投递（2-4 周）
  ↓
笔试 / 面试（4-8 周）
  ↓
Offer 谈判（1-2 周）
  ↓
入职准备
```

---

## 二、准备阶段：自我盘点

### 2.1 技能清单

| 维度 | 技能 | 熟练度 |
|------|------|--------|
| **编程** | Python、SQL | 必选 |
| **LLM 技术栈** | Prompt / RAG / Agent / LangChain | 必选 |
| **云原生** | Docker / K8s / CI/CD | 必选 |
| **集成** | SSO / OAuth / ETL | 高频 |
| **数据** | SQL / 向量库 | 必选 |
| **AI 工具** | Cursor / Claude Code / v0 | 加分 |
| **GPU** | CUDA / vLLM / TensorRT | 加分（AI 原生公司）|

### 2.2 项目清单

- 至少 3 个端到端项目
- 包含代码、文档、部署
- 有明确的业务价值
- GitHub 有展示

### 2.3 软技能

- 沟通能力（案例）
- 抗压能力（案例）
- 业务理解（行业 Know-how）
- Ownership（案例）

## 三、简历撰写

### 3.1 简历结构

```
基本信息
  ├─ 姓名、电话、邮箱、LinkedIn / GitHub
  └─ 期望职位：FDE / 解决方案工程师

教育背景
  ├─ 学校、专业、学历
  └─ GPA（突出）

工作经历（重点）
  ├─ 公司、职位、时间
  ├─ 工作内容（动词 + 量化）
  └─ 业务价值

技术栈
  ├─ 编程语言
  ├─ LLM / AI
  ├─ 云原生
  ├─ 集成
  └─ 其他

项目经验（详细 2-3 个）
  ├─ 项目背景
  ├─ 我的角色
  ├─ 技术方案
  └─ 业务结果

荣誉 / 证书 / 博客
```

### 3.2 简历要点

#### 3.2.1 突出端到端交付
- ❌ "参与了某 AI 项目"
- ✅ "主导 XX 客户大模型项目交付，覆盖 POC → 生产全周期，业务指标提升 30%"

#### 3.2.2 量化业务结果
- "提升效率 50%"
- "降低错误率 80%"
- "客户满意度 4.8/5"
- "签约金额 500 万"
- "节省成本 200 万 / 年"

#### 3.2.3 技术栈分层
- 必备技能靠前
- 加分技能靠后
- 避免堆砌罗列

### 3.3 简历长度

- 1-3 年：1 页
- 3-7 年：2 页
- 7+ 年：2-3 页

### 3.4 简历模板

- Markdown / LaTeX（推荐）
- 简洁、专业、易读
- 不用花哨模板

### 3.5 简历常见错误

- ❌ 大段技术堆砌、无业务结果
- ❌ 项目经历像"工作日志"
- ❌ 技能写很多但没深度
- ❌ 无 GitHub 展示
- ❌ 拼写错误、不专业

## 四、面试准备

### 4.1 笔试（部分公司有）

**题型**：
- 算法题（LeetCode 中等）
- 系统设计
- 业务分析

**准备**：
- LeetCode 100 题（中等难度）
- 系统设计：高频面试题
- 业务分析：FDE 场景模拟

### 4.2 技术面试

**常见问题**：

| 类别 | 问题 |
|------|------|
| **RAG** | 讲一下 RAG 的流程，如何优化？|
| **RAG** | 文档切分有哪些方式？|
| **RAG** | Embedding 模型怎么选？|
| **Agent** | ReAct、Plan-and-Execute 的区别？|
| **Agent** | Multi-Agent 怎么设计？|
| **Prompt** | CoT、ReAct 的区别？|
| **系统设计** | 设计一个高并发 RAG 服务？|
| **云原生** | K8s 的核心概念？|
| **集成** | SSO / OAuth 怎么集成？|
| **评估** | 如何评估 LLM 应用效果？|

**准备方法**：
- 整理 10-15 个核心问题答案
- 多模拟（mock interview）
- 用 STAR 法回答行为面试

### 4.3 行为面试

**常见问题**：
- 为什么想做 FDE？
- 你对 FDE 的理解是什么？
- 讲一个端到端交付的项目
- 讲一个跨部门沟通的案例
- 讲一个处理模糊需求的案例
- 讲一个 on-call / 处理故障的案例
- 讲一个说服客户的案例

**STAR 法回答**：
- **S**ituation：背景
- **T**ask：任务
- **A**ction：行动
- **R**esult：结果（量化）

### 4.4 案例面试（部分大厂有）

**类型**：模拟一个客户场景，给方案

**准备**：
- 多看 FDE 实战案例
- 多做端到端设计练习
- 学会讲业务故事

**示例问题**：
- 某银行想做智能客服，你怎么设计？
- 某制造业客户想做设备预测性维护，方案是什么？
- 某律所想做合同审查 Agent，方案如何？

### 4.5 高管面试（部分公司有）

**面对**：VP / Director

**重点**：
- 业务理解
- 行业洞察
- 长期发展

**准备**：
- 行业报告（艾瑞、IDC）
- 公司业务深度调研
- 个人长期规划

## 五、内推与投递策略

### 5.1 内推（最高效）

**内推渠道**：
- 找前同事、同学、朋友
- 找猎头（针对资深岗位）
- 社区贡献者（开源、技术大会）
- 脉脉、知乎相关

**内推优先级**：
- 朋友内推（最有效）
- 同事内推（高效）
- 猎头内推（特定岗位）
- 陌生人内推（一般）

### 5.2 投递平台

**国内**：
- 拉勾（技术岗多）
- Boss 直聘（直接聊）
- 脉脉（社交 + 求职）
- 猎聘（中高端）

**海外**：
- LinkedIn（首选）
- Indeed
- Glassdoor

### 5.3 投递节奏

| 节奏 | 说明 |
|------|------|
| **每周 5-10 个目标公司** | 不要太少也不要多到应付不过来 |
| **重点公司** | 阿里云、华为云、字节火山、蚂蚁、腾讯云 |
| **同时投递** | 3-5 家 AI 原生公司 |
| **备份** | 传统 ToB 公司的 FDE 储备岗 |

### 5.4 投递要点

#### 5.4.1 针对性
- 每个公司定制简历
- 突出公司关心的技能

#### 5.4.2 求职信
- 突出为什么选这家公司
- 表达诚意

#### 5.4.3 Follow up
- 投递后 1 周跟进
- 不要过于频繁（每周 1 次）

#### 5.4.4 多线并行
- 同时拿多个 Offer
- 不要把所有鸡蛋放一个篮子

## 六、面试常见问题详解

### 6.1 必问题

#### Q1：为什么想做 FDE？
**准备要点**：
- 体现对 FDE 的深度理解
- 结合自身经历
- 表达长期规划

#### Q2：你对 FDE 的理解是什么？
**准备要点**：
- 驻场 + 写代码 + 对业务结果负责 + 反哺产品
- 结合实际案例

#### Q3：讲一个端到端交付的项目
**STAR 法**：
- 项目背景
- 你的角色
- 关键挑战
- 解决方案
- 业务结果

#### Q4：你最熟悉的技术栈是什么？
**准备要点**：
- 不要列举，要深度
- 展示实际项目经验

#### Q5：你对薪资的期望？
**准备要点**：
- 提前调研市场行情
- 给区间（关注薪资 + 总包）

### 6.2 技术题

#### Q6：讲一下 RAG 的流程，如何优化？
**标准答案**：
```
RAG 流程：文档加载 → 切分 → Embedding → 向量库 → 检索 → Prompt 增强 → LLM 生成

优化：
- 文档切分：语义切分 > 字符切分
- Embedding：选择合适模型
- 检索：混合检索 > 单一检索
- 重排序：使用 Rerank 模型
- Prompt：明确指令 + Few-shot
```

#### Q7：Agent 和 RAG 的区别？
**标准答案**：
- RAG：检索增强生成，单次问答
- Agent：自主规划、调用工具、决策
- 关系：Agent 可以包含 RAG

#### Q8：如何处理 LLM 幻觉？
**标准答案**：
- 强制 RAG
- 引用标注
- 拒答能力
- 多次采样 + 一致性

#### Q9：K8s 的核心概念？
**标准答案**：
- Pod、Service、Deployment
- ConfigMap、Secret
- Ingress、Volume

### 6.4 案例题

**示例：某银行想做智能客服**
- **业务理解**：客服成本、效率
- **技术方案**：RAG + Agent + SSO + 私有化部署
- **挑战**：合规、数据隔离、多轮对话
- **结果**：自动解决率 70%、成本降低 35%

## 七、Offer 谈判

### 7.1 准备

- 手上至少 2-3 个 Offer
- 调研市场行情（同级别薪资范围）
- 列出自己的核心筹码

### 7.2 谈判策略

#### 7.2.1 总包谈判
- 月薪、奖金、股票
- 签字费、搬家费
- 远程办公、弹性工作
- 培训预算、福利

#### 7.2.2 不要
- 不要虚报薪资
- 不要威胁式谈判
- 不要只看月薪

#### 7.2.3 要做
- 给对方台阶下
- 表达诚意
- 用数据支撑

### 7.3 常见 Offer 决策因素

| 因素 | 权重 | 说明 |
|------|------|------|
| 总包 | ⭐⭐⭐⭐ | 最重要 |
| 公司 / 团队 | ⭐⭐⭐⭐ | 影响成长 |
| 业务前景 | ⭐⭐⭐⭐ | 影响稳定性 |
| 行业积累 | ⭐⭐⭐ | 影响未来 |
| 工作生活平衡 | ⭐⭐⭐ | 影响生活质量 |
| 城市 / 远程 | ⭐⭐ | 个人偏好 |
| 福利 | ⭐⭐ | 锦上添花 |

### 7.4 多 Offer 谈判话术

**示例**：
> "我对贵公司非常感兴趣。我手上还有其他公司的 Offer（不透露细节），期望总包在 XX 万。贵公司能否考虑调整？"

## 八、面试避坑

### 8.1 不要

- ❌ 面试前不调研公司
- ❌ 简历与实际能力不符
- ❌ 抱怨前公司 / 前领导
- ❌ 谈薪时太强硬或太软弱
- ❌ 答非所问、绕圈子
- ❌ 过度承诺自己做不到的事

### 8.2 要做

- ✅ 提前调研公司业务、文化
- ✅ 准备 5-10 个自己的故事
- ✅ 多做模拟面试
- ✅ 自信、真诚、专业
- ✅ 主动问问题（展示诚意）

## 九、入职准备

### 9.1 提前准备

- 了解团队、业务、客户
- 学习公司技术栈
- 准备行李、电脑

### 9.2 心理准备

- 高强度工作节奏
- 频繁出差 / 驻场
- 客户沟通压力

### 9.3 快速融入

- 多问、多学、多做
- 主动找 mentor
- 主动承担任务
- 主动了解业务

### 9.4 第一周要做的事

- 与团队成员 1:1
- 了解项目背景
- 学习公司技术栈
- 熟悉工作流程
- 主动认领小任务

## 十二、给不同读者的启示

### 12.1 给应届毕业生
- 多做项目、多参与开源
- 简历突出项目经验
- 准备 LeetCode + 行为面试

- 在现岗位上积累 FDE 相关经验
