## 一、5 大相邻岗位概览

| 岗位 | 全称 | 核心职责 | 与 FDE 关系 |
|------|------|---------|------------|
| SA | Solution Architect 解决方案架构师 | 设计技术方案、不写代码 | FDE 落地方案 |
| 实施工程师 | Implementation Engineer | 标准化产品部署 | FDE 接手定制 |
| 大模型算法工程师 | LLM Algorithm Engineer | 模型训练 / 微调 | FDE 反馈应用层需求 |
| 售前工程师 | Pre-Sales Engineer | 售前方案 / PoC | FDE 接续交付 |
| CSM | Customer Success Manager 客户成功经理 | 客户关系运营 | FDE 提供技术后盾 |

> 加上 FDE 自己，这 6 个岗位共同构成了 **ToB AI 公司的"客户铁三角"**：
> - 售前：拿单
> - FDE：交付
> - CSM：续约

## 二、FDE vs SA（解决方案架构师）

### 2.1 核心差异

| 维度 | SA | FDE |
|------|-----|-----|
| 工作重心 | 方案设计 | 方案落地 |
| 代码量 | 几乎不写 | 重度写 |
| 客户接触 | 售前阶段 | 全周期 |
| 驻场时间 | 偶尔出差 | 长期驻场 |
| 衡量标准 | 方案是否中标 | 业务是否跑通 |
| 业务理解 | 中 | 高 |
| 抗压能力 | 中 | 高 |
| 薪资上限 | 80 万 | 100+ 万 |

### 2.2 协作模式

**典型流程**：
1. SA 签单前出方案 → 中标
2. 项目交接给 FDE
3. FDE 实施过程中遇到架构问题，**反向咨询** SA
4. 经验丰富的 FDE 可转 SA

**协作关键点**：
- SA 的方案要"可落地"（FDE 能执行）
- FDE 的反馈要"可指导"（SA 能迭代方案）

### 2.3 一句话区分

> **SA 画蓝图，FDE 盖楼。**

### 2.4 谁更适合你？

- 想做 SA：喜欢设计、不爱写代码、爱交流、想拿高薪
- 想做 FDE：喜欢落地、爱写代码、敢抗压、爱与客户并肩

## 三、FDE vs 实施工程师

### 3.1 核心差异

| 维度 | 实施工程师 | FDE |
|------|----------|-----|
| 部署对象 | 标准化产品 | 定制化方案 |
| 代码深度 | 配置为主 | 重度写 |
| 业务理解 | 浅 | 深 |
| 架构决策 | 几乎无 | 大量 |
| 客户复杂度 | 低 | 高 |
| 抗压能力 | 中 | 高 |
| 薪资上限 | 40 万 | 100+ 万 |

### 3.2 协作模式

**典型流程**：
1. 实施工程师部署标准产品 → 项目成功
2. 复杂客户由 FDE 接手深度定制
3. 实施工程师可在工作中成长为 FDE

**协作关键点**：
- 实施工程师是"第一接触点"
- FDE 接手后实施工程师转为运维支持

### 3.3 一句话区分

> **实施工程师装软件，FDE 写软件。**

### 3.4 谁更适合你？

- 想做实施：喜欢按手册操作、不爱写代码、想稳定
- 想做 FDE：喜欢创造、爱写代码、敢抗压

---

## 四、FDE vs 大模型算法工程师

### 4.1 核心差异

| 维度 | 算法工程师 | FDE |
|------|----------|-----|
| 工作重心 | 模型本身 | 模型的应用 |
| 数学要求 | 高 | 中 |
| 写代码 | 训练代码 | 应用代码 |
| 见客户 | 不见 | 大量见 |
| 衡量标准 | 模型指标 | 业务指标 |
| 业务理解 | 浅 | 深 |
| 薪资上限 | 100+ 万 | 100+ 万 |

### 4.2 协作模式

**典型流程**：
1. 算法工程师训练模型（关注 benchmark）
2. FDE 在客户环境部署和应用（关注业务）
3. FDE 反馈客户需求给算法 → 推动模型迭代

**协作关键点**：
- 算法工程师要"可解释"（FDE 能告诉客户模型在干什么）
- FDE 要"会读论文"（理解算法团队的输出）

### 4.3 一句话区分

> **算法工程师造发动机，FDE 把发动机装进车里。**

### 4.4 谁更适合你？

- 想做算法：喜欢数学、不爱见客户、爱研究
- 想做 FDE：喜欢落地应用、爱见客户、爱跨领域

## 五、FDE vs 售前工程师

### 5.1 核心差异

| 维度 | 售前工程师 | FDE |
|------|----------|-----|
| 工作周期 | 签单前 | 签单后 |
| 核心产出 | 方案 + 报价 | 落地系统 |
| 压力来源 | 中标率 | 交付质量 |
| 客户关系 | 浅 | 深 |
| 收入影响 | 签单金额 | 续约率 |
| 业务理解 | 中 | 高 |
| 薪资上限 | 60 万 | 100+ 万 |

### 5.2 协作模式

**典型流程**：
1. 售前签单（拿合同）
2. FDE 接手交付（按合同交付）
3. 客户反馈 → 售前继续挖掘新需求 → FDE 交付

**协作关键点**：
- 售前承诺的方案 FDE 必须能落地（不能过度承诺）
- FDE 的反馈要给售前（哪些方案客户不满意）

### 5.3 一句话区分

> **售前卖未来，FDE 把未来变成现实。**

### 5.4 谁更适合你？

- 想做售前：口才好、爱社交、不爱写代码
- 想做 FDE：执行力强、爱写代码、爱落地

### 5.5 售前 FDE（新兴角色）

部分公司设"售前 FDE"角色：既负责签单、又负责交付。
- 优点：客户关系连续、信息不丢失
- 缺点：对个人能力要求极高

## 六、FDE vs CSM（客户成功经理）

### 6.1 核心差异

| 维度 | CSM | FDE |
|------|-----|-----|
| 工作重心 | 客户关系运营 | 技术交付 |
| 技术深度 | 浅 | 深 |
| 写代码 | 不写 | 重度 |
| 收入影响 | 续约 + 增购 | 一次性 + 续约 |
| 衡量标准 | NPS + 续约率 | SLA + 业务结果 |
| 出差频率 | 中 | 高 |
| 薪资上限 | 50 万 | 100+ 万 |

### 6.2 协作模式

**典型流程**：
1. FDE 交付系统
2. CSM 接手客户关系（运营、培训、续约）
3. 复杂技术问题由 FDE 支持 CSM

**协作关键点**：
- FDE 交付要有"客户体验"（CSM 能运营）
- CSM 要有"技术判断"（知道何时升级到 FDE）

### 6.3 一句话区分

> **CSM 维护关系，FDE 解决真问题。**

### 6.4 谁更适合你？

- 想做 CSM：爱社交、不爱写代码、想稳定
- 想做 FDE：爱技术、爱写代码、能抗压

## 八、职业互转路径

```
        售前 ←──→ CSM
         │           │
         ↓           ↓
         SA  ←──→  FDE  ←──→ 实施
                         │
                         ↓
                       算法
```

### 8.1 进入 FDE 的常见路径
- **实施 → FDE**：最常见，3-6 月转型
- **后端 → FDE**：技术转型，6-9 月
- **算法 → FDE**：算法 + 业务，6-9 月
- **SA → FDE**：架构转交付，3-6 月
- **售前 → FDE**：沟通转技术，9-12 月
- **CSM → FDE**：客户转技术，9-12 月

### 8.2 FDE 转出路径
- **FDE → SA**：3-5 年后（积累行业 Know-how）
- **FDE → EM**：5-8 年后（带项目 → 带团队）
- **FDE → 行业专家**：5+ 年后（深耕行业）
- **FDE → 创业**：5+ 年后（积累客户资源）
- **FDE → FDR**：8+ 年后（从工程转向研究）

## 九、FDE 在 ToB 价值链中的位置

```
客户需求 → 售前（拿单） → FDE（交付） → CSM（续约） → 销售（再增购）
                ↑                                  ↑
                └─── 经验反哺 ───┘
```

**FDE 是 ToB 价值链的核心**：
- 没有 FDE，售前卖的东西兑现不了
- 没有 FDE，CSM 没有技术后盾
- 没有 FDE，经验无法反哺产品

## 十、给不同读者的启示

### 10.1 给求职者
- 不要被"售前工程师"或"FDE"迷惑，看清核心工作
- 优先选 FDE（薪资上限高、职业护城河深）

### 10.2 给在职 FDE
- 不要羡慕 SA 的"不写代码"，那是"天花板低"
- 珍惜 FDE 的复合能力，这是长期竞争力

### 10.3 给 HR / 招聘官
- FDE 与相邻岗位的 JD 要明确区分
- 不要用"售前"或"实施"的 JD 招 FDE
