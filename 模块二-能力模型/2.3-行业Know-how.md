## 一、为什么行业 Know-how 重要

**核心观点**：
> 在 ToB 领域，**行业 Know-how 的稀缺性 > 技术能力**
> 一个有 3 年金融行业经验的 FDE，转其他行业也能快速上手

**原因**：
- **业务理解**：不同行业的业务逻辑差异巨大（金融风控 ≠ 电商推荐）
- **合规要求**：不同行业的合规要求差异巨大（金融等保 ≠ 医疗 HIPAA）
- **客户关系**：行业 Know-how 是建立客户信任的关键
- **问题判断**：知道行业常见问题、避免低级错误

**数据佐证**：
- 资深行业 FDE 的薪资比"多面手"高 30-50%
- 行业 FDE 离职后，客户流失率比普通 FDE 低 40%
- 行业 Know-how 是 FDE 转 SA / 行业专家的关键

## 二、金融行业

### 2.1 行业特点

**业务特点**：
- 强合规（等保、PCI-DSS、银保监会）
- 监管严格（人行、银保监、证监会）
- 数据敏感（客户隐私、交易数据）
- 系统复杂（核心系统、风控系统）

**技术特点**：
- 系统稳定性要求极高（5 个 9）
- 数据一致性要求极高（金融级）
- 实时性要求高（毫秒级决策）
- 灾备要求严格（同城双活、异地灾备）

### 2.2 典型场景

| 场景 | 业务价值 | 技术挑战 |
|------|---------|---------|
| **智能风控** | 实时识别欺诈 | 实时计算、特征工程、模型解释 |
| **智能投顾** | 客户画像、推荐产品 | 合规、客户分级、风险评估 |
| **智能客服** | 处理客户咨询 | 多轮对话、知识库、合规话术 |
| **信贷审批** | 自动化审批 | 数据整合、模型解释、监管报送 |
| **反洗钱** | 识别可疑交易 | 规则引擎、图计算、可疑行为分析 |
| **保险理赔** | 自动化定损 | 图像识别、文档解析、反欺诈 |

### 2.3 核心技术栈

**核心系统**：
- 核心交易系统（自研或外包）
- 风控系统（决策引擎、规则引擎）
- 数据仓库（实时 + 离线）
- 数据湖 / 数据中台

**技术栈**：
- **隐私计算**：同态加密、联邦学习、差分隐私
- **风控模型**：评分卡、机器学习、图神经网络
- **实时计算**：Flink、Kafka
- **图计算**：Neo4j、JanusGraph（图挖掘）
- **流批一体**：Kafka + Flink + Iceberg

### 2.4 合规要求

| 法规 | 适用范围 | 关键要求 |
|------|---------|---------|
| **等保 2.0** | 中国 | 分级保护、安全建设 |
| **银保监** | 银行、保险 | 数据安全、业务连续性 |
| **证监会** | 证券 | 投资者保护、信息披露 |
| **GDPR** | 欧盟 | 数据保护、用户同意 |
| **PCI-DSS** | 支付 | 支付数据保护 |
| **反洗钱（AML）** | 银行 | 可疑交易识别、监管报送 |

**FDE 必知**：
- 数据不出域
- 完整审计日志
- 模型可解释性
- 监管报送
- 客户隐私保护

### 2.5 代表客户 / 公司

**代表公司**：蚂蚁、腾讯云、华为云、字节火山、阿里云、Databricks

**客户类型**：
- 国有银行（工行、农行、中行、建行）
- 股份制银行（招商、平安、浦发）
- 城商行 / 农商行
- 保险公司（人保、平安、太保）
- 证券公司（中信、华泰）
- 消费金融（蚂蚁、京东、马上）
- 互联网金融

### 2.6 入门门槛

- 至少 3 年 Java + Python 经验
- 熟悉金融业务（信贷、风控、投顾）
- 了解金融监管要求
- **优先**：金融行业经验、PMP 认证、CFA / FRM

**避坑**：
- 不能只看技术，不懂业务
- 不能忽视合规要求
- 不能过于激进（金融行业保守）

## 三、政企行业

### 3.1 行业特点

**业务特点**：
- 强信创（国产化）
- 强合规（涉密、等级保护）
- 流程复杂（政府采购）
- 周期长（半年起步）

**技术特点**：
- 信创全栈适配
- 内网隔离
- 严格的访问控制
- 复杂的审计要求

### 3.2 典型场景

| 场景 | 业务价值 | 技术挑战 |
|------|---------|---------|
| **政务问答** | 政策解读、办事指南 | 知识更新、合规审核、政治正确 |
| **智慧城市** | 交通、安防、应急 | 多源数据、跨部门协调 |
| **司法 AI** | 文书生成、案件检索 | 法律知识库、合规审查 |
| **公文写作** | 自动生成报告 | 格式规范、政治正确 |
| **政务办公** | 自动化办公 | 集成 OA、邮件、流程 |
| **应急指挥** | 突发事件响应 | 实时数据、决策支持 |

### 3.3 核心技术栈

**信创生态**：

| 类别 | 国产化方案 | 原替代 |
|------|----------|--------|
| CPU | 鲲鹏、昇腾、海光、龙芯 | Intel、AMD |
| 操作系统 | 麒麟、统信 | Windows、Linux |
| 数据库 | 高斯、达梦、人大金仓 | Oracle、MySQL |
| 中间件 | 东方通、宝兰德 | WebLogic、JBoss |
| 大模型 | 盘古、混元、文心、GLM | GPT、Claude |

**大模型选型**：
- 华为云：盘古大模型 + 昇腾
- 阿里云：通义大模型
- 百度：文心大模型
- 智谱：GLM 大模型

### 3.4 合规要求

| 法规 | 适用范围 | 关键要求 |
|------|---------|---------|
| **等保 2.0** | 中国 | 三级以上 |
| **涉密项目** | 党政军 | 涉密资质、人员审查 |
| **政府采购法** | 中国 | 招标流程、资质要求 |
| **数据安全法** | 中国 | 数据分类分级 |
| **个人信息保护法** | 中国 | 用户同意、数据最小化 |
| **密码法** | 中国 | 国产密码 |

### 3.5 代表客户 / 公司

**代表公司**：阿里云政企、华为云、智谱 AI、腾讯云

**客户类型**：
- 中央部委（发改委、工信部、网信办）
- 地方政府（省、市、区县）
- 央国企（中石油、国家电网、烟草）
- 司法机关（法院、检察院、公安）
- 事业单位（医院、学校、研究机构）
- 军工企业（涉密资质）

### 3.6 入门门槛

- 熟悉信创生态
- 了解政企采购流程
- 抗压（项目周期长、变更多）
- **优先**：政府项目经验、信创认证、PMP

**避坑**：
- 不能过于激进（政企行业保守）
- 不能忽视合规要求（涉密项目尤其）
- 不能忽视政治正确（敏感词、政治合规）

## 四、零售 / 电商

### 4.1 行业特点

**业务特点**：
- 节奏快（双 11、618 等大促）
- 数据量大（用户行为、订单）
- 业务场景丰富（推荐、搜索、客服、运营）
- 重视 ROI

**技术特点**：
- 高并发、大流量
- 实时性要求高
- A/B 测试常态化
- 数据驱动决策

### 4.2 典型场景

| 场景 | 业务价值 | 技术挑战 |
|------|---------|---------|
| **智能客服** | 售前售后咨询 | 多轮对话、知识更新 |
| **个性化推荐** | 商品、内容 | 用户画像、实时推荐 |
| **智能搜索** | 语义搜索、跨模态 | 意图理解、多模态 |
| **内容生成** | 商品描述、营销文案 | 风格控制、合规审查 |
| **运营自动化** | 营销活动编排 | 业务流程、决策引擎 |
| **供应链优化** | 库存、调度 | 时序预测、组合优化 |
| **风控反欺诈** | 识别恶意用户 | 实时决策、规则引擎 |

### 4.3 核心技术栈

**核心系统**：
- 推荐系统（协同过滤、深度学习）
- 搜索引擎（Elasticsearch、向量检索）
- 用户画像系统
- A/B 测试平台
- 数据中台

**技术栈**：
- **大数据**：Spark、Flink、Hive、Kafka
- **推荐**：TensorFlow、PyTorch、DeepFM、DIN
- **搜索**：Elasticsearch、向量检索
- **高并发**：Redis、Kafka、HBase
- **AI 工具**：vLLM、TensorRT、ONNX Runtime

### 4.4 行业 Know-how

**核心业务指标**：
| 指标 | 含义 |
|------|------|
| GMV | 商品交易总额 |
| CTR | 点击率 |
| CVR | 转化率 |
| UV | 独立访客 |
| ARPU | 每用户平均收入 |
| 复购率 | 重复购买用户占比 |

**大促备战经验**：
- 流量预测（提前 3-6 个月）
- 压测演练（提前 1-2 个月）
- 应急预案（提前 1 个月）
- 灰度发布（按比例放量）

**库存、供应链、支付基础**：
- 库存管理（实时库存、安全库存）
- 供应链（WMS、TMS）
- 支付（聚合支付、清算）

### 4.5 代表客户 / 公司

**代表公司**：字节火山、阿里、京东、美团、Shopify

**客户类型**：
- 大型电商平台（淘宝、京东、拼多多）
- 品牌商（耐克、宝洁、可口可乐）
- 零售商（沃尔玛、家乐福、永辉）
- 跨境电商（SHEIN、Temu）
- 垂直电商（美妆、生鲜、奢侈品）

### 4.6 入门门槛

- 熟悉推荐 / 搜索业务
- 了解电商核心指标
- 有高并发经验
- **优先**：电商行业经验、大数据经验

**避坑**：
- 不能忽视大促备战
- 不能只关注 AI 不关注业务指标
- 不能忽视 A/B 测试

## 五、制造行业

### 5.1 行业特点

**业务特点**：
- 业务流程复杂（生产、供应链、质量）
- 系统异构（MES、ERP、PLM、WMS）
- 知识密集（老师傅经验）
- 重视降本增效

**技术特点**：
- OT（运营技术）/ IT 融合
- 边缘计算需求
- 实时性要求（生产调度）
- 工业协议多样性

### 5.2 典型场景

| 场景 | 业务价值 | 技术挑战 |
|------|---------|---------|
| **设备预测性维护** | 预测故障 | 时序数据、异常检测 |

| **工艺优化** | 参数调优 | 多目标优化、因果推断 |
| **工业知识库** | 老师傅经验数字化 | 知识抽取、推理 |
| **智能客服** | 售后支持 | 工业知识库 |

**技术栈**：

- **计算机视觉**：YOLO、Detectron2、工业相机

## 六、医疗行业

**业务特点**：
- 强合规（HIPAA、医疗器械法规）
- 数据敏感（病历、影像）

**技术特点**：
- 医学专业性

- 长文本（病历）
- 可解释性要求高

### 6.2 典型场景

| 场景 | 业务价值 | 技术挑战 |

| **临床决策** | 治疗方案推荐 | 知识图谱、多模态 |
| **医学影像** | 病灶识别 | 视觉模型、可解释性 |

### 6.3 核心技术栈

**医学专业**：
- ICD-10 / ICD-11（疾病分类）

## 七、法律行业

### 7.1 行业特点

**业务特点**：
- 知识密集（法条、判例）
- 文档密集（合同、诉讼材料）
- 业务专业（不同法律细分）
- 准确性要求极高

**技术特点**：
- 长文本（合同、判决书）
- 命名实体识别（法条、案件、人物）
- 知识图谱（法条关联）
- 文档理解（PDF、扫描件）

### 7.2 典型场景

| 场景 | 业务价值 | 技术挑战 |
|------|---------|---------|
| **合同审查** | 识别风险条款 | 长文本理解、命名实体 |
| **法律研究** | 法条检索、判例推荐 | 知识图谱、语义检索 |
| **诉讼支持** | 文书生成、证据分析 | 长文本生成、逻辑推理 |
| **智能客服** | 法律咨询 | 合规话术、专业边界 |
| **尽调调查** | 背景调查 | 数据整合、信息提取 |
| **知识产权** | 专利检索、分析 | 专利分类、相似度 |

### 7.3 核心技术栈

**AI 技术**：
- RAG（长文本、复杂检索）
- 命名实体识别（法条、案件、人物）
- 文档理解（PDF、扫描件）
- 多语言支持
- 知识图谱（法条关联）

**法律专业**：
- 法律条文（中国《民法典》《刑法》等）
- 判例（指导性案例、公报案例）
- 法律检索（中国裁判文书网、北大法宝）
- 法律文书（起诉状、答辩状、合同）

- 审计日志
- 司法合规（涉密案件）

### 7.5 代表客户 / 公司

**客户类型**：
- 头部律所（金杜、君合、中伦）
- 企业法务部（央企、外企法务）
- 法院（最高法、地方法院）
- 仲裁机构
- 法律科技公司

### 7.6 入门门槛

- 法律背景优先（法学生、律师）
- 熟悉 RAG / 文档处理
- 重视准确性和可解释性
- **优先**：法律行业经验、法律职业资格证

**避坑**：
- 法律不能有错（准确性第一）
- 不能忽视司法合规
- 不能忽视律师的工作流程

## 九、行业选择方法论

### 9.1 选择决策树

```
你想做 ToB 大客户？
  ├─ 是 → 高合规、高价值
  │       ├─ 金融（最高薪）
  │       ├─ 政企（最强合规）
  │       └─ 医疗（最强 Know-how 价值）
  │
  └─ 否 → 高频迭代、快速交付
          ├─ 零售/电商（最高频）
          └─ 制造（最长周期）
```

### 9.2 选择考量因素

| 因素 | 说明 |
|------|------|
| **个人兴趣** | 选自己感兴趣的行业（长期深耕）|
| **薪资** | 金融 > 政企 > 零售 > 制造 > 医疗 > 法律 |
| **成长性** | 医疗、法律是新兴蓝海 |
| **门槛** | 自己能进的行业 |
| **技术成熟度** | 高成熟度 = 风险小、低成熟度 = 机会多 |
| **地理分布** | 金融（北上深）、政企（省会）、零售（杭州、上海）|

### 9.3 转型建议

| 当前背景 | 推荐行业 |
|---------|---------|
| Java 后端 | 金融、政企 |
| Python 算法 | 医疗、法律 |
| DevOps | 政企、制造 |
| 咨询 / 解决方案 | 政企、金融 |
| 数据工程师 | 零售、金融 |
| 实施工程师 | 政企、制造 |

## 十六、给不同读者的启示（细化）

### 16.1 给应届毕业生

**行业选择是关键决策**：
- 不要只看薪资
- 考虑长期发展 + 个人兴趣
- 多与行业从业者交流
- 实习是试错的最佳方式

**持续深耕行业**：
- 选定 1-2 个行业深耕
- 横向了解其他行业
- 行业大会演讲
- 行业方法论输出

### 16.3 给公司 / 团队

**行业 Know-how 是核心竞争力**：
- 培养行业专家
- 建立行业知识库
- 行业大会赞助 / 演讲
- 与行业协会建立关系
