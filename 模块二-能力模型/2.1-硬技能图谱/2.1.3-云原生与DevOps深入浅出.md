## 一、一句话定义

**云原生 = 让 AI 应用能在生产环境可靠运行的方法论**。FDE 写出能跑的代码只是开始，**让代码在客户的复杂环境里 7×24 稳定运行**才是真本事。

---

## 二、为什么 FDE 必须学

### 2.1 客户环境的现实

> 90% 的客户生产环境是 K8s（政企金融客户 100%）。

不会 Docker / K8s 的 FDE：
- 交付时依赖运维同事
- 排查问题没有头绪
- 性能问题无法定位

### 2.2 必备能力图

```
云原生技术栈
  ├─ 容器化：Docker（必会）
  ├─ 编排：Kubernetes（必会）
  ├─ CI/CD：GitHub Actions / GitLab CI（必会）
  ├─ 监控：Prometheus + Grafana（必会）
  ├─ 日志：ELK / Loki（高频）
  ├─ 配置管理：Helm / Kustomize（高频）
  └─ 服务网格：Istio（加分）
```

### 2.3 客户部署模式

| 模式 | 客户类型 | FDE 工作量 |
|------|---------|----------|
| **公有云 SaaS** | 中小企业 | 低（5%）|
| **私有化部署** | 政企/金融 | 高（60%）|
| **混合云** | 中大型 | 中（30%）|
| **边缘部署** | 制造/IoT | 高（5%）|

## 三、核心概念图解

### 3.1 容器 vs 虚拟机

```
┌──────────────┐         ┌──────────────┐
│   虚拟机      │         │   容器        │
├──────────────┤         ├──────────────┤
│   App A      │         │   App A      │
│   Bins/Libs  │         │   Bins/Libs  │
│   Guest OS   │         ├──────────────┤
│   Hypervisor │         │   App B      │
│   Host OS    │         │   Bins/Libs  │
│   Hardware   │         ├──────────────┤
└──────────────┘         │   Container Engine │
                        │   Host OS           │
                        │   Hardware          │
                        └─────────────────────┘
  启动: 分钟级              启动: 秒级
  镜像: GB                 镜像: MB
  性能损耗: 5-10%           性能损耗: <1%
```

### 3.2 K8s 架构

```
┌─────────────────────────────────────────┐
│          Master Node（控制平面）           │
│  ┌────────┐ ┌──────┐ ┌────────────┐   │
│  │ API    │ │Sched │ │Controller   │   │
│  │Server  │ │uler  │ │Manager      │   │
│  └────────┘ └──────┘ └────────────┘   │
│  ┌──────────┐ ┌──────┐                │
│  │  etcd    │ │Cloud │                │
│  └──────────┘ └──────┘                │
└─────────────────────────────────────────┘
            ↓ 调度
┌─────────────────────────────────────────┐
│          Worker Node（工作节点）           │
│  ┌──────┐ ┌──────┐ ┌──────┐           │
│  │ Pod1 │ │ Pod2 │ │ Pod3 │           │
│  │App A │ │App B │ │App C │           │
│  └──────┘ └──────┘ └──────┘           │
│  ┌──────────┐ ┌──────────┐            │
│  │  kubelet │ │  kube-   │            │
│  │          │ │  proxy   │            │
│  └──────────┘ └──────────┘            │
└─────────────────────────────────────────┘
```

### 3.3 FDE 部署流程

```
开发环境
  └─ docker build + docker run
       ↓
测试环境
  └─ docker push + K8s deploy
       ↓
预发布环境
  └─ 灰度发布（10% 流量）
       ↓
生产环境
  └─ 全量发布 + 监控
```

### 示例 8：GitHub Actions CI/CD

```yaml
# .github/workflows/deploy.yml
name: Build and Deploy

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: |
          pip install -r requirements.txt
          pip install pytest

      - name: Run tests
        run: pytest tests/

  build:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v3

      - name: Build and push Docker image
        run: |
          docker build -t registry.customer.com/ai-service:${{ github.sha }} .
          docker push registry.customer.com/ai-service:${{ github.sha }}

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Deploy to K8s
        run: |
          echo "${{ secrets.K8S_CONFIG }}" > kubeconfig.yaml
          kubectl --kubeconfig=kubeconfig.yaml \
            set image deployment/ai-service \
            ai-service=registry.customer.com/ai-service:${{ github.sha }}
          kubectl --kubeconfig=kubeconfig.yaml \
            rollout status deployment/ai-service
```

```python
# app.py - 添加 Prometheus 指标
from prometheus_client import Counter, Histogram, generate_latest, CONTENT_TYPE_LATEST
from fastapi import FastAPI, Response
import time

app = FastAPI()

# 指标
REQUEST_COUNT = Counter(
    "ai_request_total",
    "Total AI requests",
    ["endpoint", "status"],
)

REQUEST_LATENCY = Histogram(
    "ai_request_latency_seconds",
    "AI request latency",
    ["endpoint"],
)

LLM_TOKEN_USAGE = Counter(
    "ai_llm_tokens_total",
    "Total LLM tokens used",
    ["model", "type"],
)


@app.middleware("http")
async def metrics_middleware(request, call_next):
    start = time.time()
    response = await call_next(request)
    latency = time.time() - start

    REQUEST_COUNT.labels(
        endpoint=request.url.path,
        status=response.status_code,
    ).inc()
    REQUEST_LATENCY.labels(
        endpoint=request.url.path,
    ).observe(latency)

    return response


@app.get("/metrics")
def metrics():
    return Response(
        generate_latest(),
        media_type=CONTENT_TYPE_LATEST,
    )


@app.post("/query")
def query(req: QueryRequest):
    response = client.chat.completions.create(...)

    LLM_TOKEN_USAGE.labels(
        model="gpt-4o-mini",
        type="prompt",
    ).inc(response.usage.prompt_tokens)
    LLM_TOKEN_USAGE.labels(
        model="gpt-4o-mini",
        type="completion",
    ).inc(response.usage.completion_tokens)

    return response
```

```python
# logging_config.py
import logging
import json
from datetime import datetime


class JSONFormatter(logging.Formatter):
    """JSON 格式日志（方便 Loki 收集）"""
    def format(self, record):
        log_data = {
            "timestamp": datetime.utcnow().isoformat(),
            "level": record.levelname,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
        }
        if record.exc_info:
            log_data["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_data, ensure_ascii=False)
```

### 示例 11：健康检查（必备）

```python
# health_check.py
from fastapi import FastAPI
from sqlalchemy import text
import redis
import openai

app = FastAPI()


@app.get("/health")
def health():
    """Liveness 探针：进程是否活着"""
    return {"status": "ok"}


@app.get("/ready")
def ready():
    """Readiness 探针：是否能服务请求"""
    checks = {}

    # 1. 数据库
    try:
        db.execute(text("SELECT 1"))
        checks["database"] = "ok"
    except Exception as e:
        checks["database"] = f"error: {e}"

    # 2. Redis
    try:
        redis_client.ping()
        checks["redis"] = "ok"
    except Exception as e:
        checks["redis"] = f"error: {e}"

    # 3. OpenAI API（可选）
    try:
        openai.Model.list()
        checks["openai"] = "ok"
    except Exception:
        checks["openai"] = "unreachable"

    # 任意一个失败则未就绪
    all_ok = all(v == "ok" for v in checks.values())
    return {"ready": all_ok, "checks": checks}, 200 if all_ok else 503
```

### 示例 12：优雅关闭（生产级必备）

```python
# graceful_shutdown.py
from fastapi import FastAPI
import signal
import asyncio

app = FastAPI()

shutdown_event = asyncio.Event()


@app.post("/query")
async def query(req: QueryRequest):
    """处理请求 - 收到 shutdown 信号会等待当前请求完成"""
    try:
        # 长任务可能需要取消
        result = await asyncio.wait_for(
            process_query(req.question),
            timeout=30.0,
        )
        return {"answer": result}
    except asyncio.TimeoutError:
        return {"error": "timeout"}, 504


def handle_shutdown(signum, frame):
    """收到 SIGTERM 信号"""
    print("收到关闭信号，等待当前请求完成...")
    shutdown_event.set()


signal.signal(signal.SIGTERM, handle_shutdown)
signal.signal(signal.SIGINT, handle_shutdown)


@app.on_event("shutdown")
async def shutdown():
    """K8s 关闭时调用"""
    print("开始优雅关闭...")
    # 1. 停止接收新请求
    # 2. 等待进行中的请求完成（最多 30 秒）
    # 3. 关闭数据库连接
    # 4. 清理资源
    await asyncio.sleep(0)  # 让出控制权
    print("关闭完成")
```

## 五、6 个 FDE 实战场景

### 5.1 场景 1：客户私有化部署

**业务**：客户要 AI 系统部署到他们机房

**做法**：
```bash
# 1. 准备镜像（air-gapped 环境）
# 在能上网的机器上拉镜像
docker pull registry.customer.com/ai-service:v1.0
docker save ai-service:v1.0 -o ai-service.tar

# 2. 复制到客户内网
scp ai-service.tar root@customer:/tmp/

# 3. 客户机器加载镜像
ssh root@customer
docker load -i /tmp/ai-service.tar

# 4. 部署
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f ingress.yaml
```

**遇到的问题**：
- 客户 K8s 版本老（1.18）→ 调整 YAML
- 没有外网（air-gapped）→ 镜像导入
- GPU 节点需要特殊调度 → nodeSelector
- 客户审计要求 → 镜像签名

### 5.2 场景 2：灰度发布（金丝雀）

**业务**：新版本上线，先给 10% 流量

**做法**：
```yaml
# 蓝绿部署 v2（10% 流量）
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ai-service-v2
spec:
  replicas: 1  # 10% 副本
  selector:
    matchLabels:
      app: ai-service
      version: v2
  template:
    metadata:
      labels:
        app: ai-service
        version: v2
    spec:
      containers:
      - name: ai-service
        image: registry.customer.com/ai-service:v2.0
---
# Service 同时指向 v1 和 v2
apiVersion: v1
kind: Service
metadata:
  name: ai-service
spec:
  selector:
    app: ai-service  # 选中所有 version
  ports:
  - port: 80
    targetPort: 8000
```

**步骤**：
1. 部署 v2（10% 副本）
2. 观察 v2 监控（错误率、延迟）
3. 如果好，扩大 v2 到 50%、100%
4. 缩容 v1 到 0
5. 删除 v1

### 5.3 场景 3：CI/CD 完整 pipeline

**业务**：代码 push → 自动测试 → 自动部署

**做法**：见示例 8（GitHub Actions）

**关键点**：
- PR 触发测试（不部署）
- main 分支触发部署
- 用 tag/SHA 做镜像版本
- 自动回滚（出错时）

### 5.4 场景 4：生产事故排查

**业务**：服务挂了，客户打电话

**排查流程**：
```bash
# 1. 看 Pod 状态
kubectl get pods
# NAME                          READY   STATUS    RESTARTS
# ai-service-7d8f9c5b6-x2k4j   0/1     Error     5

# 2. 看 Pod 详情
kubectl describe pod ai-service-7d8f9c5b6-x2k4j
# 看到 Events: BackoffLimitExceeded, OOMKilled

# 3. 看日志
kubectl logs ai-service-7d8f9c5b6-x2k4j --previous
# 看到 MemoryError

# 4. 看监控
# Grafana：内存使用 100%，缓慢增长 → 内存泄漏

# 5. 临时扩容
kubectl scale deployment/ai-service --replicas=5

# 6. 排查代码
# 找到泄漏点：缓存无界增长

# 7. 修复 + 重新部署
```

**常用命令速查**：
```bash
kubectl get pods                          # 查看 Pod
kubectl describe pod <pod>                # 详情
kubectl logs <pod>                        # 日志
kubectl logs <pod> --previous             # 上次容器日志
kubectl exec -it <pod> -- /bin/bash       # 进入容器
kubectl top pod                           # 资源使用
kubectl get events --sort-by='.lastTimestamp'  # 事件
```

### 5.5 场景 5：客户 GPU 资源调度

**业务**：客户有 4 张 GPU 卡，2 个服务要分配

**做法**：
```yaml
# gpu-pod.yaml
apiVersion: apps/v1
```

### 5.6 场景 6：日志排查（ELK/Loki）

**业务**：用户反馈查询慢，怎么排查？

**做法**：
```python
# 在代码中加 trace_id
import uuid
import logging
from fastapi import Request

logger = logging.getLogger(__name__)


@app.middleware("http")
async def trace_middleware(request: Request, call_next):
    trace_id = request.headers.get("X-Trace-Id") or str(uuid.uuid4())

    # 记录请求开始
    logger.info(
        "request_start",
        extra={
            "trace_id": trace_id,
            "method": request.method,
            "path": request.url.path,
        },
    )

    # 记录每个关键步骤
    start = time.time()
    response = await call_next(request)
    latency = time.time() - start

    logger.info(
        "request_end",
        extra={
            "trace_id": trace_id,
            "status": response.status_code,
            "latency": latency,
        },
    )

    response.headers["X-Trace-Id"] = trace_id
    return response
```

## 六、5 个常见坑与避坑

### 6.1 坑 1：镜像太大

**症状**：
- 镜像 2GB，部署慢
- 占用磁盘多

**避坑**：
- 多阶段构建（见示例 2）
- 用 slim 基础镜像
- `.dockerignore` 排除无关文件
- 合并 RUN 命令

### 6.2 坑 2：没有健康检查

**症状**：
- Pod 启动但服务没起来，流量进来失败
- 进程死锁但 K8s 不知道

**避坑**：
- 加 liveness + readiness 探针
- 探针要真实（不是只返回 200）
- 见示例 11

### 6.3 坑 3：配置硬编码

**症状**：
- 改个配置要重新打包
- 客户环境不同，频繁出错

**避坑**：
- 用 ConfigMap + Secret
- 12 因素应用原则
- 不同环境用不同 values

### 6.4 坑 4：资源限制不合理

**症状**：
- 没设 limits → 进程吃光资源
- limits 设太小 → 频繁 OOM

**避坑**：
- 设 requests + limits
- 监控实际使用，调整
- 内存泄漏服务加 restart policy

### 6.5 坑 5：忽略优雅关闭

**症状**：
- Pod 删除时，正在处理的请求被中断
- 数据丢失、用户体验差

**避坑**：
- 加 SIGTERM 处理
- K8s terminationGracePeriodSeconds
- 见示例 12

## 十三、Operator 开发进阶

### 13.1 什么是 Operator

> Operator = 用软件管理有状态应用（K8s API 扩展）

**为什么 FDE 要学 Operator**：
- 客户常有"AI 服务集群"这种复杂部署
- Operator 让部署、升级、备份自动化
- 信创 / 金融客户对自动化要求高

### 13.2 Operator 模式

```python
# operator_demo.py - 简化版 Operator
from kubernetes import client, watch
from kubernetes.client.rest import ApiException
import kopf  # Operator 框架


@kubernetes_operator.py - 简化版 Operator
@kopf.timer("aideployments.example.com", interval=10)
async def reconcile_ai_deployment(spec, status, **kwargs):
    """调和 AI 部署资源"""
    name = kwargs["name"]
    namespace = kwargs["namespace"]

    # 1. 获取当前状态
    current_replicas = status.get("replicas", 0)
    desired_replicas = spec.get("replicas", 1)

    # 2. 调整 Deployment
    if current_replicas != desired_replicas:
        await scale_deployment(name, namespace, desired_replicas)

    # 3. 检查健康
    if not is_healthy(name, namespace):
        await restart_pods(name, namespace)

    # 4. 更新状态
    return {
        "replicas": desired_replicas,
        "phase": "Running" if is_healthy(...) else "Pending",
    }


def scale_deployment(name, namespace, replicas):
    apps_v1 = client.AppsV1Api()
    body = {"spec": {"replicas": replicas}}
    try:
        apps_v1.patch_namespaced_deployment_scale(
            name, namespace, body,
        )
    except ApiException as e:
        print(f"Exception: {e}")
```

## 十八、故障排查手册

### 18.1 故障 1：Pod 一直 Pending

**症状**：Pod 卡在 Pending 状态

**排查**：
```bash
# 1. 看事件
kubectl describe pod <pod-name>

# 2. 常见原因
- 资源不足（CPU/内存/GPU）
- 节点选择器不匹配
- PVC 没绑定
- 镜像拉取失败
```

**解决**：
- 加资源 / 调度到合适节点
- 检查 nodeSelector / tolerations
- 修复 PVC

### 18.2 故障 2：Pod OOMKilled

**症状**：Pod 被 OOMKilled 杀死

**排查**：
```bash
# 1. 看内存使用
kubectl top pod <pod-name>

# 2. 看 JVM/Python 内存
# Python: tracemalloc, memory_profiler
# vLLM: --gpu-memory-utilization 调低
```

**解决**：
- 调大 limits.memory
- 优化代码（流式处理）
- 用更小的模型

### 18.3 故障 3：服务间调用超时

**症状**：A 调用 B 超时

**排查**：
```bash
# 1. 网络
kubectl exec -it <pod-a> -- curl <service-b>:port

# 2. DNS
kubectl exec -it <pod-a> -- nslookup <service-b>

# 3. mTLS（Service Mesh）
istioctl proxy-config secret <pod-a>
```

**解决**：
- 修复网络策略
- 调超时
- 加重试

### 18.4 故障 4：GPU 调度不到

**症状**：Pod 调度失败，nvidia.com/gpu 不足

**排查**：
```bash
# 1. 看 GPU 资源
kubectl describe nodes | grep nvidia.com/gpu

# 2. 看谁在用
kubectl get pods -o json | \
  jq '.items[] | select(.spec.containers[].resources.limits."nvidia.com/gpu") | .metadata.name'
```

**解决**：
- 加 GPU 节点
- 减少副本
- 用 MIG 切分

### 18.5 故障 5：镜像拉取失败

**症状**：`ImagePullBackOff`

**排查**：
```bash
# 1. 看事件
kubectl describe pod <pod-name>

# 2. 手动拉
docker pull <image>
```

**解决**：
- 检查镜像名 / tag
- 检查 imagePullSecrets
- 用私有 Harbor

### 18.6 故障 6：HPA 不工作

**症状**：HPA 不扩容

**排查**：
```bash
# 1. 看 HPA 状态
kubectl describe hpa

# 2. 看 metrics
kubectl top pods

# 3. 检查 metrics-server
kubectl get pods -n kube-system | grep metrics
```

**解决**：
- 安装 metrics-server
- 配置正确资源 request
- 检查 HPA 算法

## 二十、面试题精选

### Q1：K8s 中 Pod 和 Container 区别？
**A**：
- Container：运行时（一个进程组）
- Pod：一组紧密耦合的容器（共享网络、存储）
- 一个 Pod 可有多个 Container（如 sidecar）

### Q2：Deployment 和 StatefulSet 区别？
**A**：
- Deployment：无状态，适合 Web
- StatefulSet：有状态，每个 Pod 有固定身份
- AI 推理用 Deployment，Milvus/Postgres 用 StatefulSet

### Q3：HPA 工作原理？
**A**：
- 监控 metrics（CPU/GPU/自定义）
- 达到阈值自动扩缩
- 注意：必须配 resources.requests

### Q4：Deployment 滚动更新如何暂停？
**A**：`kubectl rollout pause deployment/<name>`

### Q5：Pod 卡在 CrashLoopBackOff 怎么排查？
**A**：
- `kubectl logs` 看应用日志
- `kubectl describe pod` 看事件
- 常见原因：配置错、依赖服务不通、镜像错

### Q6：Service 三种类型？
**A**：
- ClusterIP：仅集群内
- NodePort：节点端口
- LoadBalancer：云厂商 LB
- ExternalName：DNS 别名

### Q7：GPU 怎么在 K8s 调度？
**A**：
- 安装 NVIDIA Device Plugin
- Pod spec 加 `nvidia.com/gpu: 1`
- 节点必须装了驱动

### Q8：Operator 是什么？什么时候用？
**A**：
- Operator = 用代码管理 K8s 资源
- 适用：有状态应用、复杂部署、自动化运维
