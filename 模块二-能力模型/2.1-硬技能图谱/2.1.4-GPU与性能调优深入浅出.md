## 三、核心概念图解

### 3.1 GPU 架构

```
┌────────────────────────────────────────┐
│              GPU                       │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │ SM 0 │ │ SM 1 │ │ SM 2 │ │ SM 3 │  │  ← 计算单元
│  └──────┘ └──────┘ └──────┘ └──────┘  │
│  ┌────────────────────────────────┐    │
│  │     Global Memory（显存）       │    │  ← 24-80GB
│  └────────────────────────────────┘    │
│  ┌────────┐ ┌────────┐ ┌────────┐     │
│  │ L2     │ │ L1     │ │Register│     │  ← 缓存
│  └────────┘ └────────┘ └────────┘     │
└────────────────────────────────────────┘

  GPU = 多核 SIMD + 大显存 + 高带宽
  vs
  CPU = 少核 + 复杂分支 + 大缓存
```

### 3.2 LLM 推理过程

```
输入："什么是 RAG？"
  ↓
[1] Tokenization（分词）          ← CPU
  ↓
[2] Embedding（向量化）            ← GPU（计算密集）
  ↓
[3] Prefill（处理所有输入）        ← GPU（并行快）
  ↓
[4] Decoding（逐 Token 生成）      ← GPU（串行慢）⭐
  ↓
输出："RAG 是..."

性能瓶颈：Decoding 阶段（必须逐 token 生成）
```

### 3.3 推理优化全景

```
优化层次
  ├─ 模型层
  │   ├─ 量化（INT8/INT4）
  │   ├─ 剪枝
  │   └─ 蒸馏（小模型）
  ├─ 系统层
  │   ├─ KV Cache 优化
  │   ├─ PagedAttention（vLLM）
  │   ├─ Continuous Batching
  │   └─ Speculative Decoding
  ├─ 硬件层
  │   ├─ 多 GPU（TP/PP）
  │   └─ 量化硬件支持
  └─ 服务层
      ├─ 缓存（结果缓存、Prompt 缓存）
      ├─ 批处理
      └─ 负载均衡
```

### 3.4 FDE 性能调优流程

```
[1] 压测（基线）
   ↓
[2] 定位瓶颈（profile）
   ↓
[3] 选择优化策略
   ↓
[4] 实施优化
   ↓
[5] 再次压测（对比）
   ↓
[6] 监控线上（持续）
```

```python
# check_gpu.py
import torch

def gpu_info():
    """查看 GPU 信息"""
    if not torch.cuda.is_available():
        return "无可用 GPU"

    info = []
    for i in range(torch.cuda.device_count()):
        props = torch.cuda.get_device_properties(i)
        info.append({
            "id": i,
            "name": props.name,
            "total_memory_gb": props.total_memory / 1024**3,
            "compute_capability": f"{props.major}.{props.minor}",
        })
    return info


# 使用
```

```python
def quantize_awq():
    """AWQ 量化（速度接近 FP16，显存只需 1/4）"""

    model.save_quantized(quant_path)
    tokenizer.save_pretrained(quant_path)

    # 体积：14GB → 4GB（节省 70%）
```

### 示例 6：性能压测

```python
# benchmark.py - 压测工具（FDE 必备）
import time
import asyncio
from openai import AsyncOpenAI


async def benchmark(
    base_url: str,
    model: str,
    num_requests: int = 100,
    concurrency: int = 10,
    prompt: str = "什么是 RAG？用 100 字介绍。",
):
    """压测 LLM 服务"""
    client = AsyncOpenAI(base_url=base_url, api_key="EMPTY")

    semaphore = asyncio.Semaphore(concurrency)
    latencies = []
    errors = 0
    start = time.time()

    async def one_request():
        nonlocal errors
        async with semaphore:
            try:
                t1 = time.time()
                response = await client.chat.completions.create(
                    model=model,
                    messages=[{"role": "user", "content": prompt}],
                    max_tokens=200,
                )
                t2 = time.time()
                latencies.append(t2 - t1)
            except Exception as e:
                errors += 1
                print(f"错误：{e}")

    # 并发执行
    await asyncio.gather(*[one_request() for _ in range(num_requests)])

    total_time = time.time() - start

    # 统计
    latencies.sort()
    result = {
        "total_requests": num_requests,
        "successful": num_requests - errors,
        "errors": errors,
        "concurrency": concurrency,
        "total_time_s": round(total_time, 2),
        "throughput_qps": round(num_requests / total_time, 2),
        "latency_p50_s": round(latencies[len(latencies) // 2], 3),
        "latency_p95_s": round(latencies[int(len(latencies) * 0.95)], 3),
        "latency_p99_s": round(latencies[int(len(latencies) * 0.99)], 3),
    }

    return result


# 使用
result = asyncio.run(benchmark(
    base_url="http://localhost:8000/v1",
    model="qwen",
    num_requests=100,
    concurrency=20,
))

print(result)
# {'total_requests': 100, 'successful': 100, 'errors': 0,
#  'throughput_qps': 15.5, 'latency_p50_s': 1.2,
#  'latency_p95_s': 2.1, 'latency_p99_s': 3.5}
```

### 示例 8：缓存优化（减少重复调用）

```python
# semantic_cache.py - 语义缓存（省钱！）
import hashlib
from diskcache import Cache
from openai import OpenAI

client = OpenAI()
cache = Cache("./llm_cache")


def get_cache_key(prompt: str, model: str) -> str:
    """生成缓存 key"""
    return hashlib.md5(f"{model}:{prompt}".encode()).hexdigest()


def query_with_cache(prompt: str, model: str = "gpt-4o-mini") -> str:
    """带缓存的查询"""
    cache_key = get_cache_key(prompt, model)

    # 查缓存
    cached = cache.get(cache_key)
    if cached:
        return cached

    # 调用 LLM
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
    )
    answer = response.choices[0].message.content

    # 写缓存（TTL 1 天）
    cache.set(cache_key, answer, expire=86400)

    return answer


# 使用
print(query_with_cache("什么是 RAG？"))  # 调用 LLM
print(query_with_cache("什么是 RAG？"))  # 命中缓存，秒回
```

```python
# semantic_cache_v2.py - 语义级缓存（相似问题也命中）
import numpy as np
from openai import OpenAI

client = OpenAI()
embedding_cache = []  # [(embedding, answer)]


def get_embedding(text: str) -> list:
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text,
    )
    return response.data[0].embedding


def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))


def query_with_semantic_cache(prompt: str, threshold: float = 0.95) -> str:
    """语义级缓存"""
    # 1. Embedding
    emb = get_embedding(prompt)

    # 2. 查相似缓存
    for cached_emb, cached_answer in embedding_cache:
        sim = cosine_similarity(emb, cached_emb)
        if sim >= threshold:
            print(f"语义缓存命中（相似度 {sim:.3f}）")
            return cached_answer

    # 3. 调用 LLM
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
    )
    answer = response.choices[0].message.content

    # 4. 写缓存
    embedding_cache.append((emb, answer))

    return answer
```

```python
# streaming_response.py - 流式响应，首 token 延迟 < 1s
from openai import OpenAI

client = OpenAI()


def stream_query(prompt: str):
    """流式查询（用户逐字看到结果）"""
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        stream=True,
    )

    for chunk in stream:
        if chunk.choices[0].delta.content:
            content = chunk.choices[0].delta.content
            print(content, end="", flush=True)
            yield content


# 使用
for token in stream_query("写一首关于 AI 的诗"):
    pass  # 实时输出
```

### 示例 10：成本分析

```python
# cost_analysis.py
# FDE 必备：成本测算
def estimate_cost(
    model: str,
    input_tokens_per_request: int,
    output_tokens_per_request: int,
    qps: int,
    seconds_per_day: int = 86400,
) -> dict:
    """估算 Token 成本"""
    # 各模型价格（每 1K token，元）
    prices = {
        "gpt-4o": {"input": 0.018, "output": 0.072},
        "gpt-4o-mini": {"input": 0.0011, "output": 0.0044},
        "qwen-72b": {"input": 0.004, "output": 0.012},
    }

    p = prices[model]

    # 每日 token
    daily_requests = qps * seconds_per_day
    daily_input_tokens = daily_requests * input_tokens_per_request
    daily_output_tokens = daily_requests * output_tokens_per_request

    # 每日成本（元）
    daily_input_cost = (daily_input_tokens / 1000) * p["input"]
    daily_output_cost = (daily_output_tokens / 1000) * p["output"]
    daily_cost = daily_input_cost + daily_output_cost

    return {
        "model": model,
        "qps": qps,
        "daily_requests": daily_requests,
        "daily_cost_yuan": round(daily_cost, 2),
        "monthly_cost_yuan": round(daily_cost * 30, 2),
        "yearly_cost_yuan": round(daily_cost * 365, 2),
    }


# 使用
print(estimate_cost(
    model="gpt-4o",
    input_tokens_per_request=500,
    output_tokens_per_request=300,
    qps=10,
))
# {'qps': 10, 'daily_cost_yuan': 15552.0, 'monthly_cost_yuan': 466560.0, ...}
```

## 六、5 个常见坑与避坑

### 6.1 坑 1：没设显存利用率

**症状**：
- 默认只用了 60% 显存
- 浪费资源

**避坑**：
```bash
# 设置显存利用率 90%
--gpu-memory-utilization 0.9
```

### 6.2 坑 2：批处理没启用

**症状**：
- 串行处理 100 个请求，要 100 秒
- 启用批处理只需 10 秒

**避坑**：
- vLLM / TGI 默认开 Continuous Batching
- 自研必须实现动态批处理

### 6.3 坑 3：max_model_len 设太大

**症状**：
- max_model_len=32768，KV Cache 占用 50% 显存
- 实际请求最长 4096，浪费

**避坑**：
- 根据实际场景设 max_model_len
- 不要设大

### 6.4 坑 4：不压测直接上线

**症状**：
- 预估能扛 100 QPS
- 实际 30 QPS 就崩

**避坑**：
- 上线前必压测（见示例 6）
- 压测要看 P95 / P99，不是平均值
- 测持续负载，不是瞬时

### 6.5 坑 5：忽视量化损失

**症状**：
- 4bit 量化后，效果差 5%
- 不测试就上线

**避坑**：
- 量化后必做评估（见 2.1.8）
- A/B 测试
- 关键场景用高精度（FP16/INT8）

## 十二、PagedAttention 原理深入

### 12.1 为什么需要 PagedAttention

> 传统 KV Cache 显存浪费严重（碎片化、预留）

```
传统 KV Cache（连续分配）：
┌─────────────────────────────────┐
│  请求 1 (1024 tokens)  [浪费]   │
│  请求 2 (512 tokens)   [浪费]   │
│  请求 3 (2048 tokens)  [浪费]   │
└─────────────────────────────────┘
浪费率：60-80% 显存

PagedAttention（分页）：
┌──┬──┬──┬──┬──┬──┬──┬──┐
│  │  │  │  │  │  │  │  │  4K 一页
└──┴──┴──┴──┴──┴──┴──┴──┘
按需分配，零浪费
```

### 12.2 核心思想

借鉴操作系统虚拟内存分页：
- **Block**：固定大小（16 tokens）的 KV 块
- **Block Table**：每个请求的逻辑块 → 物理块映射
- **共享**：beam search、parallel sampling 可共享前缀

### 12.3 性能数据

| 指标 | 传统 | PagedAttention | 提升 |
|------|------|---------------|------|
| **显存利用率** | 30-40% | 90%+ | 2.5x |
| **吞吐量** | 200 QPS | 2000 QPS | 10x |
| **最大并发** | 50 | 500+ | 10x |
| **TTFT（首 token 延迟）** | 200ms | 50ms | 4x |

### 12.4 实现关键

```python
# vllm 简化版逻辑
class PagedAttention:
    def __init__(self, block_size=16, num_blocks=1000):
        self.block_size = block_size
        self.num_blocks = num_blocks
        self.kv_cache = torch.zeros(num_blocks, 2, 32, 1024, 128)
        self.free_blocks = list(range(num_blocks))

    def allocate_blocks(self, seq_len):
        """按需分配 block"""
        num_needed = (seq_len + self.block_size - 1) // self.block_size
        block_table = []
        for _ in range(num_needed):
            block_id = self.free_blocks.pop()
            block_table.append(block_id)
        return block_table

    def append_kv(self, block_table, new_k, new_v):
        """追加新的 K/V 到 block"""
        # 找到最后一个 block
        last_block = block_table[-1]
        # 写入
        self.kv_cache[last_block, 0] = new_k
        self.kv_cache[last_block, 1] = new_v
```

## 十三、Speculative Decoding（投机解码）

### 13.1 核心思想

> 用小模型"猜"多个 token，大模型一次性验证

```
普通解码：
[大模型] → token 1 → [大模型] → token 2 → [大模型] → token 3
（3 次大模型调用）

投机解码：
[小模型] → 猜 3 个 token
[大模型] → 1 次验证，接受 N 个
（1 次大模型调用，加速 2-3x）
```

### 13.2 适用场景

| 场景 | 加速效果 | 原因 |
|------|----------|------|
| 文本续写 | 2-3x | 可预测性高 |
| 翻译 | 2-3x | 答案唯一 |
| 代码生成 | 1.5-2x | 模式化 |
| 创意写作 | 1.2-1.5x | 不易预测 |
| 长输出 | 3-5x | 收益放大 |

### 13.3 实现

```python
# speculative_decoding.py
class SpeculativeDecoder:
    def __init__(self, draft_model, target_model):
        self.draft = draft_model  # 小模型
        self.target = target_model  # 大模型

    async def generate(self, prompt, max_tokens=100, gamma=5):
        """生成（投机解码）"""
        # 1. 小模型生成 gamma 个候选
        candidates = await self.draft.generate(
            prompt, max_tokens=gamma,
        )

        # 2. 大模型一次性验证
        accepted = 0
        target_logits = await self.target.score(
            prompt + candidates,
        )

        # 3. 接受检验
        for i, token in enumerate(candidates):
            prob_draft = self.draft_prob[i]
            prob_target = self.target_prob[i]
            # 接受概率
            if random.random() < min(1, prob_target / prob_draft):
                accepted += 1
            else:
                # 拒绝，从 target 重新采样
                break

        return candidates[:accepted] + await self.target.sample(...)
```

### 13.4 实战：用 vLLM 投机解码

```bash

  --model Qwen/Qwen2.5-72B-Instruct \
  --speculative-model Qwen/Qwen2.5-1.5B-Instruct \
  --num-speculative-tokens 5 \
  --gpu-memory-utilization 0.9
```

## 十八、故障排查手册

### 18.1 故障 1：CUDA OOM

**症状**：`CUDA out of memory`

**排查**：
```bash
# 1. 看显存
nvidia-smi

# 2. 看进程
nvidia-smi pmon -c 1

# 3. 看 vLLM 日志
grep -i "memory" vllm.log
```

**解决**：
- 减小 `gpu-memory-utilization`
- 用更小模型 / 量化
- 减小 `max-num-seqs`
- 增加 GPU

### 18.2 故障 2：推理慢

**症状**：QPS 远低于预期

**排查**：
```bash
# 1. 看 GPU 利用率
nvidia-smi dmon -c 10

# 2. 看是不是在等 IO
iostat -x 1

# 3. 看是不是 CPU bound
top
```

**解决**：
- 加 GPU
- 启用投机解码
- 减少 max-model-len
- 用 Prefix Caching

### 18.3 故障 3：首 Token 延迟高

**症状**：用户等待 5s 才看到第一个字

**解决**：
- 用流式输出
- 减少 prompt 长度
- 启用 Prefix Caching
- 改用更小模型做 prefill

### 18.4 故障 4：量化后效果差

**症状**：INT4 量化后回答质量明显下降

**解决**：
- 改用 AWQ（量化感知）
- 用 GPTQ + 校准数据集
- 仅量化部分层
- 关键层保持 FP16

### 18.5 故障 5：多 GPU 通信慢

**症状**：Tensor Parallel 加速比不线性

**解决**：
- 用 NVLink 而不是 PCIe
- 减少通信次数（更大的 chunk）
- 用更高效的 AllReduce
- 考虑 Pipeline Parallel

### 18.6 故障 6：模型加载慢

**症状**：冷启动 5 分钟

**解决**：
- 用 SSD 而非 HDD
- 启用模型并行加载
- 用 safetensors
- 预热 + Snapshot

### 18.7 故障 7：推理结果不稳定

**症状**：相同输入，不同输出

**解决**：
- 设 `temperature=0`
- 设 seed
- 检查 batch 是否影响
- 用 Greedy Decoding

### 19.1 踩坑 1：客户 GPU 型号太老

**症状**：P40 / M40 / 1080Ti
**教训**：
- 提前确认 GPU 型号
- 老卡算力不够，跑不动大模型

### 19.2 踩坑 2：CUDA 版本冲突

**症状**：各种找不到 .so
**教训**：
- 统一 CUDA 驱动版本
- 用容器固定 CUDA 版本
- 写清楚依赖文档

### 19.3 踩坑 3：模型放错位置

**症状**：模型从 OSS 下载慢
**教训**：
- 模型放客户内网
- 用内网 Harbor
- 提前传过去

### 19.4 踩坑 4：量化后显存反而变大

**症状**：INT4 比 FP16 显存占用大
**原因**：量化框架 bug 或权重没释放
**教训**：
- 升级量化框架
- 检查 weight loading 逻辑

### 19.5 踩坑 5：并发数一高就崩

**症状**：QPS > 100 OOM
**原因**：max-num-seqs 设太大
**教训**：
- 按 GPU 显存精确计算
- 加监控（显存 + QPS）
- 调小并发数

### 19.6 踩坑 6：Prefix Cache 不生效

**症状**：相同前缀没省时间
**原因**：prefix-caching 没启用
**教训**：
- `enable-prefix-caching: true`
- 检查 system prompt 是否一致

### 19.7 踩坑 7：投机解码反而变慢

**症状**：投机解码后 QPS 下降
**原因**：小模型选错，验证开销 > 收益
**教训**：
- 选好 draft model（同系列小模型）
- 调 gamma（猜测 token 数）
- 评估实际收益

### 19.8 踩坑 8：分布式推理通信瓶颈

**症状**：4 卡跑不出 4 倍
**教训**：
- 必须 NVLink
- 调 TP/PP 配比
- 用最新 NCCL

### Q3：量化有哪些方法？区别？
**A**：
- GPTQ：训练后量化，权重量化
- AWQ：激活感知权重量化
- SmoothQuant：激活 + 权重都量化
- INT8 vs INT4：精度 vs 显存

### Q4：Tensor Parallel vs Pipeline Parallel？
**A**：
- TP：层内拆分（需要 NVLink）
- PP：层间拆分（可用 PCIe）
- TP+PP 组合常用

### Q5：vLLM 为什么比 HuggingFace 快？
**A**：
- PagedAttention（显存高效）
- Continuous Batching（动态批）
- Prefix Caching

### Q6：什么是 Speculative Decoding？
**A**：
- 小模型猜，大模型验证
- 加速 2-3x
- 适合可预测场景

### Q7：怎么选 GPU？
**A**：
- 训练：H100/A100（大显存 + 高速互联）
- 推理：A10/L4（性价比）
- 国产：昇腾 910B、海光
- 看：显存、算力、互联、功耗

### Q8：什么是 FP8？
**A**：
- 8 位浮点
- 显存减半
- 推理效果好（接近 FP16）
- H100 原生支持
