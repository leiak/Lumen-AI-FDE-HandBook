## 一、一句话定义

**向量与数据 = 让 LLM 用对资料的能力**。RAG 效果好不好，70% 取决于检索质量，30% 取决于 LLM。

## 二、为什么 FDE 必须学

### 2.1 RAG 效果的核心

> RAG 准确率 = 检索准确率 × LLM 准确率

检索错了，LLM 再强也答不对。

### 2.2 FDE 的数据工作

| 工作 | 占比 |
|------|------|
| 数据清洗 | 30% |
| Embedding 选型 | 10% |
| 向量库选型 | 10% |
| 检索策略调优 | 30% |
| 评估 | 20% |

### 2.3 数据流程

```
原始数据（PDF/Word/HTML/DB）
  ↓
[1] 清洗（去格式、纠错）
  ↓
[2] 分块（Chunking）
  ↓
[3] Embedding（向量化）
  ↓
[4] 入库（向量库 + 元数据）
  ↓
[5] 检索（相似度 / 混合 / Rerank）
  ↓
[6] 增强 Prompt
  ↓
LLM 生成
```

## 三、核心概念图解

### 3.1 Embedding 原理

```
文本："什么是 RAG？"
  ↓
[Embedding 模型]
  ↓
向量：[0.12, -0.34, 0.56, ..., 0.78]  ← 1536 维

相似度计算：
  文本 A 向量 ── 内积 ─┐
                      ├─ 相似度（0-1）
  文本 B 向量 ── 内积 ─┘

余弦相似度：
  cos(θ) = (A · B) / (||A|| × ||B||)
  越接近 1，越相似
```

### 3.2 向量库架构

```
┌────────────────────────────────────┐
│          向量库                     │
├────────────────────────────────────┤
│  ┌──────┐  ┌──────┐  ┌──────┐    │
│  │ Index│  │Index │  │Index │    │  ← 向量索引（HNSW/IVF）
│  └──────┘  └──────┘  └──────┘    │
│  ┌──────┐  ┌──────┐  ┌──────┐    │
│  │Vector│  │Vector│  │Vector│    │  ← 向量数据
│  └──────┘  └──────┘  └──────┘    │
│  ┌──────┐  ┌──────┐  ┌──────┐    │
│  │Meta  │  │Meta  │  │Meta  │    │  ← 元数据（过滤用）
│  └──────┘  └──────┘  └──────┘    │
└────────────────────────────────────┘
```

### 3.3 检索方式对比

```
关键词检索（BM25）
  ├─ 原理：词频统计
  ├─ 优势：精确匹配、速度快
  └─ 劣势：无语义理解

向量检索
  ├─ 原理：Embedding 相似度
  ├─ 优势：语义理解
  └─ 劣势：精确词匹配差

混合检索
  ├─ 原理：BM25 + 向量加权
  ├─ 优势：兼顾两者
  └─ 劣势：复杂、调参

Rerank
  ├─ 原理：粗排 + 精排
  ├─ 优势：精度高
  └─ 劣势：额外成本
```

### 3.4 FDE 选型决策

```
需要：
  ├─ 语义理解（如"天气"和"下雨"）→ 向量检索
  ├─ 精确词（如产品型号）→ BM25
  └─ 都要 → 混合检索

规模：
  ├─ < 1 万条 → Chroma / Faiss
  ├─ 1 万 - 100 万 → Qdrant / Weaviate
  └─ > 100 万 → Milvus

部署：
  ├─ 简单 → Chroma（本地）
  ├─ 自托管 → Qdrant / Weaviate
  └─ 大规模集群 → Milvus
```

### 示例 2：相似度计算

```python
# 02_similarity.py
import numpy as np
from openai import OpenAI

client = OpenAI()


def get_embedding(text: str) -> list:
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text,
    )
    return response.data[0].embedding


def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))


# 准备文档
docs = [
    "RAG 是检索增强生成",
    "今天天气真好",
    "检索增强生成是一种技术",
    "我喜欢吃苹果",
]

# Embedding
doc_embeddings = [get_embedding(d) for d in docs]

# 查询
query = "什么是 RAG？"
query_emb = get_embedding(query)

# 计算相似度
similarities = [cosine_similarity(query_emb, de) for de in doc_embeddings]

# 排序
ranked = sorted(zip(docs, similarities), key=lambda x: -x[1])
for doc, sim in ranked:
    print(f"{sim:.3f}  {doc}")

# 0.832  RAG 是检索增强生成
# 0.815  检索增强生成是一种技术
# 0.231  今天天气真好
# 0.198  我喜欢吃苹果
```

### 示例 3：基础向量库（Chroma）

```python
# 03_chroma_basic.py
import chromadb
from openai import OpenAI

client = OpenAI()
chroma = chromadb.PersistentClient(path="./chroma_db")
collection = chroma.get_or_create_collection(
    name="docs",
    metadata={"hnsw:space": "cosine"},  # 用余弦相似度
)


def add_docs(docs: list, ids: list, metadatas: list = None):
    """添加文档"""
    # 自动用 Chroma 默认的 embedding 函数
    # 也可以自定义：
    # embeddings = [get_embedding(d) for d in docs]
    # collection.add(embeddings=embeddings, documents=docs, ids=ids, metadatas=metadatas)

    collection.add(
        documents=docs,
        ids=ids,
        metadatas=metadatas or [{}] * len(docs),
    )


def query(question: str, top_k: int = 3, where: dict = None):
    """检索"""
    results = collection.query(
        query_texts=[question],
        n_results=top_k,
        where=where,  # 元数据过滤
    )
    return results

    ids=["1", "2", "3", "4"],
    metadatas=[
        {"category": "年假"},
        {"category": "报销"},
        {"category": "远程"},
        {"category": "加班"},
    ],
)
```

### 示例 5：Milvus 生产级

```python
# 05_milvus.py - 大规模向量库
from pymilvus import (
    connections, Collection, CollectionSchema, FieldSchema,
    DataType, utility,
)
import numpy as np

# 1. 连接
connections.connect("default", host="localhost", port="19530")

# 2. 定义 Schema
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=1536),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=2000),
    FieldSchema(name="category", dtype=DataType.VARCHAR, max_length=100),
    FieldSchema(name="source", dtype=DataType.VARCHAR, max_length=500),
]
schema = CollectionSchema(fields, "客户文档库")

# 3. 创建 Collection
collection_name = "customer_kb"
if utility.has_collection(collection_name):
    utility.drop_collection(collection_name)
collection = Collection(collection_name, schema)

# 4. 创建索引（HNSW - 高性能）
index_params = {
    "metric_type": "COSINE",
    "index_type": "HNSW",
    "params": {"M": 16, "efConstruction": 200},
}
collection.create_index("embedding", index_params)

# 5. 插入数据
embeddings = np.random.rand(1000, 1536).astype(np.float32).tolist()
texts = [f"文档 {i}" for i in range(1000)]
categories = ["政策" if i % 2 == 0 else "流程" for i in range(1000)]
sources = [f"file_{i}.pdf" for i in range(1000)]

collection.insert([embeddings, texts, categories, sources])
collection.load()

# 6. 检索
query_embedding = np.random.rand(1536).astype(np.float32).tolist()
results = collection.search(
    data=[query_embedding],
    anns_field="embedding",
    param={"metric_type": "COSINE", "params": {"ef": 100}},
    limit=5,
    expr='category == "政策"',  # 过滤
    output_fields=["text", "category", "source"],
)

for hits in results:
    for hit in hits:
        print(f"距离: {hit.distance:.3f}, 文本: {hit.entity.get('text')}")
```

### 示例 6：智能分块（Chunking）

```python
# 06_chunking.py - 高级分块策略
from langchain.text_splitter import (
    RecursiveCharacterTextSplitter,
    CharacterTextSplitter,
    MarkdownTextSplitter,
)


def chunk_by_recursive(text: str, chunk_size: int = 500, overlap: int = 50):
    """递归分块（推荐）"""
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=overlap,
        separators=["\n\n", "\n", "。", "！", "？", ".", " ", ""],
    )
    return splitter.split_text(text)


def chunk_by_markdown(text: str, chunk_size: int = 500):
    """按 Markdown 结构分块"""
    splitter = MarkdownTextSplitter(chunk_size=chunk_size)
    return splitter.split_text(text)


def chunk_by_semantic(text: str, model=None):
    """语义分块（更智能）"""
    from langchain_experimental.text_splitter import SemanticChunker
    from langchain_openai import OpenAIEmbeddings

    embeddings = OpenAIEmbeddings()
    splitter = SemanticChunker(
        embeddings,
        breakpoint_threshold_type="percentile",
    )
    return splitter.split_text(text)


# 使用
text = """
第一章 政策总则
...
第二章 年假规定
...
第三章 报销流程
...
"""
chunks = chunk_by_recursive(text, chunk_size=300)
for i, chunk in enumerate(chunks):
    print(f"Chunk {i}: {chunk[:50]}...")
```

### 示例 7：混合检索（BM25 + 向量）

```python
# 07_hybrid_search.py - 混合检索
from langchain.retrievers import BM25Retriever, EnsembleRetriever
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain.schema import Document
from rank_bm25 import BM25Okapi
import jieba

# 准备文档
docs = [
    Document(page_content="RAG 是检索增强生成，结合了检索和生成"),
    Document(page_content="向量数据库是存储 Embedding 的数据库"),
    Document(page_content="GPT-4 是 OpenAI 的大语言模型"),
    Document(page_content="Fine-tuning 是微调预训练模型"),
]

# 1. BM25 检索（中文用 jieba 分词）
def chinese_tokenizer(text):
    return list(jieba.cut(text))

bm25_retriever = BM25Retriever.from_documents(
    docs,
    preprocess_func=chinese_tokenizer,
)
bm25_retriever.k = 3

# 2. 向量检索
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(docs, embeddings)
vector_retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 3. 混合检索
ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.4, 0.6],  # 向量略高
)

# 查询
query = "什么是 RAG？"
results = ensemble_retriever.get_relevant_documents(query)
for doc in results:
    print(doc.page_content)
```

### 示例 9：Query 改写

```python
# 09_query_rewrite.py - 让检索更准
from openai import OpenAI

client = OpenAI()


def rewrite_query(question: str, history: list = None) -> str:
    """Query 改写（处理多轮对话、口语化问题）"""

    history_str = "\n".join([
        f"{'用户' if m['role'] == 'user' else 'AI'}: {m['content']}"
        for m in (history or [])
    ])

    prompt = f"""基于对话历史，将用户问题改写为独立的、适合检索的查询。

要求：
1. 补全省略的主语、宾语
2. 去除口语化表达
3. 保持原意
4. 输出 1-2 句话

对话历史：
{history_str}

用户问题：{question}

改写后："""

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
    )
    return response.choices[0].message.content.strip()


# 使用
# 多轮对话场景
history = [
    {"role": "user", "content": "什么是 RAG？"},
    {"role": "assistant", "content": "RAG 是检索增强生成..."},
]

rewritten = rewrite_query("它有什么优势？", history)
print(rewritten)
# "RAG（检索增强生成）相比传统生成方法有什么优势？"
```

```python
# pii_masking.py
import re


def mask_pii(text: str) -> str:
    """PII 脱敏"""
    # 手机号
    text = re.sub(
        r'1[3-9]\d{9}',
        '1XX-XXXX-XXXX',
        text
    )
    # 身份证
    text = re.sub(
        r'\d{17}[\dXx]',
        'XXXXXXXXXXXXXXXXXX',
        text
    )
    # 邮箱
    text = re.sub(
        r'[\w.-]+@[\w.-]+',
        'XXX@XXX.com',
        text
    )
    return text


# 使用
text = "张三的手机是 13800138000，身份证 110101199001011234"
masked = mask_pii(text)
print(masked)
# "张三的手机是 1XX-XXXX-XXXX，身份证 XXXXXXXXXXXXXXXXXX"
```

## 六、5 个常见坑与避坑

### 6.1 坑 1：分块不智能

**症状**：
- 文档按固定 500 字切，破坏语义
- 一个完整句子被切断

**避坑**：
- 用 RecursiveCharacterTextSplitter
- 按段落、章节分块
- 保留 overlap（50-100 字）

### 6.2 坑 2：用默认 Embedding

**症状**：
- 用 OpenAI 默认 embedding
- 中文场景效果差

**避坑**：
- 中文用 BGE / M3E
- 大规模用 BGE-large
- 看 benchmark 选

### 6.3 坑 3：只做向量检索

**症状**：
- 检索时漏掉关键词匹配
- 准确率低

**避坑**：
- 用混合检索（BM25 + 向量）
- 用 Rerank 提升精度

### 6.4 坑 4：不更新向量库

**症状**：

## 十三、ColBERT 进阶

### 13.1 ColBERT 原理深入

> 传统 embedding：句子 → 1 个向量
> ColBERT：每个 token → 1 个向量

```
传统：
"AI 改变世界" → [0.1, 0.2, ..., 0.9]（单向量）

ColBERT：
"AI"    → [0.1, 0.2, ..., 0.8]
"改变"  → [0.3, 0.1, ..., 0.7]
"世界"  → [0.2, 0.3, ..., 0.9]
（多向量）
```

### 13.2 MaxSim 评分

```python
# ColBERT 相似度计算
def max_similarity(query_emb, doc_emb):
    """
    query_emb: [Q, D]  Q=query token 数
    doc_emb:  [D, D]  D=doc token 数
    """
    # 1. 计算所有 (query_token, doc_token) 相似度
    sim_matrix = query_emb @ doc_emb.T  # [Q, D]

    # 2. 每个 query token 取最相似的 doc token
    max_sim = sim_matrix.max(axis=1)  # [Q]

    # 3. 求和
    return max_sim.sum()
```

## 十四、Hybrid Search 进阶

### 14.1 什么是 Hybrid Search

> BM25（关键词）+ 向量（语义）= 互补

```
查询："苹果手机信号不好"
- BM25 匹配"苹果""手机""信号""不好" → 找含这些词文档
- 向量匹配语义（"iPhone 网络差"）→ 找意思接近文档
- 混合：综合两者 → 召回更全
```

### 14.2 RRF 融合算法

```python
# reciprocal_rank_fusion.py
def reciprocal_rank_fusion(results_list: list, k: int = 60) -> list:
    """
    results_list: 多个检索结果列表
    每个结果: [{"id": "...", "score": ...}, ...]
    """
    fused_scores = {}

    for results in results_list:
        for rank, item in enumerate(results):
            doc_id = item["id"]
            # RRF 公式: 1 / (k + rank)
            if doc_id not in fused_scores:
                fused_scores[doc_id] = 0
            fused_scores[doc_id] += 1 / (k + rank + 1)

    # 排序
    sorted_results = sorted(
        fused_scores.items(),
        key=lambda x: -x[1],
    )
    return [{"id": doc_id, "score": score} for doc_id, score in sorted_results]


# 使用
bm25_results = bm25_search(query, k=20)
vector_results = vector_search(query, k=20)
final_results = reciprocal_rank_fusion([bm25_results, vector_results])
```

### 14.3 权重调优

```python
# weighted_fusion.py
def weighted_fusion(bm25_results, vector_results, alpha=0.5):
    """
    alpha: 向量权重（0-1）
    1-alpha: BM25 权重
    """
    fused = {}

    for item in bm25_results:
        fused[item["id"]] = {
            "score": (1 - alpha) * item["score"],
            "text": item.get("text", ""),
        }

    for item in vector_results:
        if item["id"] in fused:
            fused[item["id"]]["score"] += alpha * item["score"]
        else:
            fused[item["id"]] = {
                "score": alpha * item["score"],
                "text": item.get("text", ""),
            }

    return sorted(fused.items(), key=lambda x: -x[1]["score"])
```

**权重选择**：
- 关键词重要（精确匹配）：alpha=0.3
- 语义重要（概念匹配）：alpha=0.7
- 平衡：alpha=0.5
- **用评估集调优**

### 14.4 完整 Hybrid Search 实现

```python
# hybrid_search.py
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer
import numpy as np


class HybridSearcher:
    def __init__(self, model_name="BAAI/bge-m3"):
        self.model = SentenceTransformer(model_name)
        self.bm25 = None
        self.documents = []

    def index(self, documents: list):
        """索引文档"""
        self.documents = documents

        # BM25 索引
        tokenized = [doc.lower().split() for doc in documents]
        self.bm25 = BM25Okapi(tokenized)

        # 向量索引
        self.doc_embeddings = self.model.encode(
            documents,
            normalize_embeddings=True,
            show_progress_bar=True,
        )

    def search(self, query: str, top_k: int = 10, alpha: float = 0.5):
        """Hybrid 检索"""
        # 1. BM25 检索
        bm25_scores = self.bm25.get_scores(query.lower().split())
        bm25_top_k = np.argsort(bm25_scores)[-top_k:][::-1]

        # 2. 向量检索
        query_emb = self.model.encode(query, normalize_embeddings=True)
        sim_scores = self.doc_embeddings @ query_emb
        vector_top_k = np.argsort(sim_scores)[-top_k:][::-1]

        # 3. 融合
        fused = self._rrf([
            [(i, bm25_scores[i]) for i in bm25_top_k],
            [(i, sim_scores[i]) for i in vector_top_k],
        ])

        # 4. 返回
        return [
            {
                "id": i,
                "text": self.documents[i],
                "score": score,
            }
            for i, score in fused[:top_k]
        ]

    def _rrf(self, results_list, k=60):
        fused = {}
        for results in results_list:
            for rank, (idx, score) in enumerate(results):
                if idx not in fused:
                    fused[idx] = 0
                fused[idx] += 1 / (k + rank + 1)
        return sorted(fused.items(), key=lambda x: -x[1])
```

```python
# hard_negative_mining.py
def mine_hard_negatives(queries, corpus, model, top_k=100, n=10):
    """挖掘 hard negative"""
    hard_negatives = {}

    for query in queries:
        # 1. 检索 top-k
        query_emb = model.encode(query)
        corpus_emb = model.encode(corpus)
        scores = corpus_emb @ query_emb
        top_indices = np.argsort(scores)[-top_k:]

        # 2. 排除真正正样本
        # 3. 取 top 1% 难负样本
        hard_negs = top_indices[-n:]
        hard_negatives[query] = [corpus[i] for i in hard_negs]

    return hard_negatives
```

```python
# production_search.py
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from elasticsearch import Elasticsearch
from pymilvus import MilvusClient
from sentence_transformers import SentenceTransformer, CrossEncoder
import logging

logger = logging.getLogger(__name__)

app = FastAPI(title="Hybrid Search Service")

# 初始化
es = Elasticsearch(["http://es:9200"])
milvus = MilvusClient(uri="http://milvus:19530")
embedder = SentenceTransformer("BAAI/bge-m3")
reranker = CrossEncoder("BAAI/bge-reranker-large")


class SearchRequest(BaseModel):
    query: str
    top_k: int = 10
    alpha: float = 0.5
    enable_rerank: bool = True


class SearchResult(BaseModel):
    doc_id: str
    text: str
    score: float
    source: str


@app.post("/search")
async def search(req: SearchRequest) -> list:
    """完整检索流程"""
    try:
        # 1. BM25 检索
        bm25_results = bm25_search(req.query, k=20)

        # 2. 向量检索
        vector_results = vector_search(req.query, k=20)

        # 3. 融合
        fused = reciprocal_rank_fusion([
            bm25_results, vector_results,
        ], alpha=req.alpha)

        # 4. Rerank（可选）
        if req.enable_rerank:
            fused = rerank_results(req.query, fused, top_k=req.top_k)
        else:
            fused = fused[:req.top_k]

        return [
            SearchResult(
                doc_id=item["id"],
                text=item["text"],
                score=item["score"],
                source=item.get("source", ""),
            )
            for item in fused
        ]
    except Exception as e:
        logger.error(f"Search failed: {e}")
        raise HTTPException(status_code=500, detail=str(e))


def bm25_search(query, k=20):
    """BM25 检索"""
    body = {
        "query": {"match": {"text": query}},
        "size": k,
    }
    response = es.search(index="docs", body=body)
    return [
        {
            "id": hit["_id"],
            "text": hit["_source"]["text"],
            "score": hit["_score"],
        }
        for hit in response["hits"]["hits"]
    ]


def vector_search(query, k=20):
    """向量检索"""
    query_vec = embedder.encode(query).tolist()
    results = milvus.search(
        collection_name="docs",
        data=[query_vec],
        limit=k,
        output_fields=["text", "doc_id"],
    )
    return [
        {
            "id": hit["entity"]["doc_id"],
            "text": hit["entity"]["text"],
            "score": hit["distance"],
        }
        for hit in results[0]
    ]


def rerank_results(query, results, top_k=10):
    """Rerank"""
    pairs = [(query, r["text"]) for r in results]
    scores = reranker.predict(pairs)

    for r, score in zip(results, scores):
        r["rerank_score"] = float(score)

    results = sorted(results, key=lambda x: -x["rerank_score"])
    return results[:top_k]
```

## 十九、故障排查手册

### 19.1 故障 1：检索召回率低

**症状**：检索结果不准

**排查**：
```python
# 1. 检查分块
print(f"平均 chunk 大小: {avg_chunk_size}")
print(f"chunk 数量: {len(chunks)}")

# 2. 检查 embedding
print(f"embedding 维度: {emb.shape}")

# 3. 看 top-k 文档
for r in results[:5]:
    print(f"score: {r['score']}, text: {r['text'][:100]}")
```

**解决**：
- 改分块策略
- 用更好 Embedding
- 加 Rerank
- 加 query expansion

### 19.2 故障 2：检索慢

**症状**：检索 > 1s

**排查**：
```bash
# 1. 看索引
milvus_cli collection describe -c docs

# 2. 看慢日志
tail -f milvus.log | grep "slow"
```

**解决**：
- 加节点
- 建索引（IVF_PQ / HNSW）
- 减小 top_k

### 19.3 故障 3：内存爆

**症状**：向量库 OOM

**解决**：
- 减少副本
- 量化（PQ）
- 减小向量维度
- 加内存

### 19.4 故障 4：检索结果不相关

**症状**：返回结果明显跑题

**排查**：
- Embedding 模型不适配
- 文档预处理有问题
- 检索参数不对

**解决**：
- 换 Embedding（领域专用）
- 改分块
- 调 alpha

### 19.5 故障 5：混合检索权重不对

**症状**：BM25 太强或向量太强

**解决**：
- 用评估集调 alpha
- 通常 0.4-0.6
- 关键场景用 Rerank

### 19.6 故障 6：增量更新失败

**症状**：新增文档检索不到

**解决**：
- 看 upsert 日志
- 检查 ID 冲突
- 重建索引

## 二十、FDE 踩坑实录

### 20.1 踩坑 1：客户文档全是扫描 PDF

**教训**：
- 必须先 OCR（PaddleOCR、TextIn）
- 表格特殊处理（Camelot、TableTransformer）

### 20.2 踩坑 2：分块大小错

**症状**：检索不准 / 上下文超长
**教训**：
- 中文建议 256-512 字
- 看业务调整
- 用 ParentDocumentRetriever

### 20.3 踩坑 3：Embedding 模型太弱

**症状**：中文检索召回率低
**教训**：
- 必须用中文专用（BGE、M3E）
- 不要用英文模型硬套

### 20.4 踩坑 4：没用 Rerank

**症状**：Top-10 准确率不足
**教训**：
- 加 Rerank 提升 10-15%
- 必加

### 20.5 踩坑 5：忽略 metadata 过滤

**症状**：检索跨租户、跨时间
**教训**：
- 必须用 metadata 过滤
- 租户、时间、类型

### 20.6 踩坑 6：query 不预处理

**症状**：口语化 query 检索差
**教训**：
- Query rewrite（HyDE、Rewrite）
- 加 query expansion

### 20.7 踩坑 7：评估不充分

**症状**：上线后效果差
**教训**：
- 必须建评估集（100+ query）
- 上线前评估

### 20.8 踩坑 8：忘记删除测试数据

**症状**：用户搜到测试文档
**教训**：
- 上线前清理
- 区分 prod / test

## 二十一、面试题精选

### Q1：为什么 RAG 比 Fine-tuning 好？
**A**：
- RAG：知识更新、引用可追溯
- Fine-tuning：成本高、知识陈旧
- 优先 RAG

### Q2：BM25 和 向量检索 区别？
**A**：
- BM25：关键词匹配，精确
- 向量：语义匹配，召回高
- 互补，Hybrid 更好

### Q3：什么是 ColBERT？优势？
**A**：
- 每个 token 一个向量
- MaxSim 评分
- 召回率高 15%+
- 索引大、慢

### Q4：如何选 Embedding 模型？
**A**：
- 看语言（中文/英文/多语言）
- 看领域（通用/医学/法律）
- 看数据规模
- 用 MTEB 评分

### Q5：什么是 Rerank？为什么需要？
**A**：
- 二次排序（Cross-Encoder）
- 提升 Top-K 准确率
- 慢，但准

### Q6：分块策略有哪些？
**A**：
- 固定大小（256/512）
- 句子分块
- 段落分块
- 递归分块
- 语义分块

### Q7：如何处理超长文档？
**A**：
- ParentDocumentRetriever
- 小块检索，大块返回
- 滑动窗口

### Q8：如何评估检索效果？
**A**：
- Recall@K
- MRR
- NDCG
- Hit Rate
