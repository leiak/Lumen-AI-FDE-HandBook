## 一、为什么需要评估工程

> 没有评估就没有改进，没有评估就无法证明价值

### 1.1 业务侧需求
- 客户要"看到 AI 真的有用"
- 业务部门要"看到 ROI"
- 高管要"看到风险可控"

### 1.2 技术侧需求
- 模型升级了，效果是否提升？
- Prompt 改了，效果是否变化？
- 数据更新了，是否引入新问题？
- 竞争对手模型，是否值得切换？

### 1.3 FDE 为什么必须懂评估工程

FDE 的核心职责之一是**对业务结果负责**，而业务结果的量化离不开评估体系。

- 客户问"AI 真的有用吗？" — 需要评估数据
- 客户问"哪个版本更好？" — 需要 A/B 测试
- 客户问"上线有风险吗？" — 需要回归测试
- 自己想"我的方案哪里可以优化？" — 需要评估反馈

**评估工程不是"算法团队的事"，而是 FDE 的基本功。**

## 二、评估的 4 个层级

### 2.1 模型层评估（算法团队主导，FDE 配合）

**核心问题**：模型本身好不好？

**评估指标**：
- 准确率、召回率、F1
- BLEU、ROUGE（生成质量）
- 困惑度（Perplexity）
- 幻觉率
- 拒答率

**典型工具**：
- HuggingFace Evaluate
- OpenAI Evals
- 自研评估脚本

**FDE 参与方式**：
- 准备评估数据集
- 在客户场景下验证模型效果
- 与算法团队沟通评估结果

### 2.2 应用层评估（FDE 主导）

**核心问题**：应用层整体效果如何？

**评估指标**：
- 任务完成率（用户问 100 个问题，AI 答对几个）
- 用户满意度（NPS、星级评分）
- 平均处理时间
- 转人工率
- 重做率（用户不满意再次提问）

**典型工具**：
- LangSmith / Langfuse
- DeepEval
- RAGAS
- 自研评估 dashboard

**FDE 主导方式**：
- 设计评估指标
- 搭建评估 pipeline
- 持续监控 + 定期报告

### 2.3 业务层评估（业务方主导，FDE 协助）

**核心问题**：AI 给业务带来什么价值？

**评估指标**：
- 转化率变化（推荐场景）
- 成本降低（客服场景）
- 效率提升（运营场景）
- 收入增长（销售场景）
- 客户满意度（NPS）

**FDE 协助方式**：
- 与业务方共同定义指标
- 提供数据埋点
- 定期输出业务效果报告

### 2.4 用户体验评估（持续监测）

**核心问题**：用户真实感受如何？

**评估指标**：
- NPS（净推荐值）
- 满意度调研
- 留存率（用户是否继续使用）
- 投诉率

## 三、评估指标体系详解

### 3.1 准确性指标

| 指标 | 含义 | 计算 |
|------|------|------|
| 准确率 | 正确答案占比 | 正确数 / 总数 |
| 召回率 | 正确项被找到的比例 | 找到的 / 应找到的 |
| F1 | 准确率 + 召回率的调和平均 | 2 * 准确率 * 召回率 / (准确率 + 召回率) |
| 答案正确率 | 答案与标准答案一致的比例 | 正确数 / 总数 |
| 事实一致性 | 答案与原文一致 | 人工评估 |
| 引用准确性 | 引用的内容是否真实存在 | 人工评估 |

### 3.2 性能指标

| 指标 | 含义 | 目标 |
|------|------|------|
| TTFT（首 Token 延迟） | 用户输入到第一个 Token 返回的时间 | <1s |
| TPS（Tokens/s） | 每秒生成 Token 数 | >30 |
| QPS（Queries/s） | 每秒查询数 | 取决于业务 |
| 总延迟 | 整个响应完成时间 | <5s |
| 并发能力 | 同时处理多少请求 | 100+ |

### 3.3 成本指标

| 指标 | 含义 |
|------|------|
| 单次对话成本 | 每次对话花费的人民币 |
| Token 使用量 | 输入 + 输出的 Token 总数 |
| GPU 利用率 | GPU 实际使用率 |
| TCO（总拥有成本） | 项目全周期成本 |

### 3.4 可靠性指标

| 指标 | 含义 | 目标 |
|------|------|------|
| SLA | 服务等级协议 | 99.9%+ |
| 错误率 | 请求失败比例 | <0.1% |
| 异常处理能力 | 异常情况下的表现 | 优雅降级 |
| 数据持久性 | 数据不丢失 | 99.999% |

### 3.5 安全合规指标

| 指标 | 含义 |
|------|------|
| 幻觉率 | 答案与事实不一致的比例 |
| 越狱成功率 | 绕过安全限制的成功率 |
| 数据泄露率 | 敏感数据泄露的比例 |
| 合规检查通过率 | 通过合规检查的比例 |

## 四、评估方法详解

### 4.1 自动化评估

**适用场景**：
- 批量回归测试
- CI/CD 集成
- 大量样本评估

**方法**：

| 方法 | 原理 | 工具 |
|------|------|------|
| 基于规则 | 精确匹配、字符串相似度 | DeepEval |
| 基于模型 | LLM-as-Judge | OpenAI Evals |
| 基于 Embedding | 语义相似度 | HuggingFace |
| 基于分类 | 分类模型评估 | 自研 |

**优势**：
- 速度快、成本低
- 可重复、可对比
- 可集成到 CI/CD

**局限**：
- 不能完全替代人工评估
- 对复杂场景评估不准

### 4.2 人工评估

**适用场景**：
- 效果验证、客户汇报
- 复杂场景评估
- 标注数据生产

**方法**：
- **专家标注**：领域专家评估
- **众包标注**：众包平台（如 Scale AI）
- **客户评估**：让客户业务方评估
- **A/B 反馈**：用户反馈对比

**注意事项**：
- 标注标准要清晰
- 评估人员要培训
- 多评估员对比（一致性）
- 反馈渠道要畅通

### 4.3 A/B 测试

**适用场景**：对比新旧版本、不同方案

**方法**：
- 流量切分（10% / 50% / 100%）
- 对照组 / 实验组
- 显著性检验
- 长期观察

**工具**：
- 自研 AB 平台
- Optimizely（商业）
- GrowthBook（开源）
- 字节火山 A/B（自家）

**关键点**：
- 流量切分要随机
- 评估指标要明确
- 观察周期要足够
- 排除干扰因素

### 4.4 线上监控

**适用场景**：生产环境实时监控

**方法**：
- 实时统计业务指标
- 用户反馈收集
- 异常告警
- Trace 分析

**工具**：
- Prometheus + Grafana
- LangSmith / Langfuse
- 自研 dashboard

## 五、幻觉检测专项

### 5.1 幻觉的 3 种类型

| 类型 | 例子 |
|------|------|
| **事实性幻觉** | 模型编造不存在的事实（如不存在的论文） |
| **逻辑性幻觉** | 推理过程错误（如数学计算错误） |
| **引用性幻觉** | 引用的内容不存在（如虚假法条） |

### 5.2 检测方法

#### 5.2.1 基于原文（RAG 场景）
- 检查答案是否与原文一致
- 检查答案是否在原文中能找到

**工具**：
- RAGAS（Faithfulness 指标）
- TruLens
- DeepEval（HallucinationMetric）

#### 5.2.2 基于事实
- 与权威数据源对比（如 Wikipedia、官方文档）
- 用更强的模型评估

**工具**：
- FactScore
- HaluEval

#### 5.2.3 基于模型
- 用更强的模型来评估
- LLM-as-Judge

#### 5.2.4 多次采样
- 多次生成，比较一致性
- SelfCheckGPT

### 5.3 应对策略

| 策略 | 说明 |
|------|------|
| **强制 RAG** | 让模型基于检索内容回答 |
| **引用标注** | 让用户看到来源 |
| **拒答能力** | 不知道就说不知道 |
| **多次采样 + 一致性** | 多次生成，结果一致才输出 |
| **知识图谱** | 约束模型不编造 |

## 六、评估体系搭建 5 步法

### 6.1 第一步：定义指标（与业务方对齐）

**关键动作**：
- 与业务方共同定义评估指标
- 区分技术指标和业务指标
- 设定指标（pass / fail 阈值）

**输出**：
- 评估指标清单
- 评估目标（KPI）

### 6.2 第二步：准备数据

**关键动作**：
- 收集历史数据（用户对话、运营数据）
- 构造测试集（覆盖正常、边界、异常）
- 标注数据（人工标注）

**输出**：
- 评估数据集
- 标注规范

### 6.3 第三步：搭建平台

**关键动作**：
- 自动化评估 pipeline
- 评估结果可视化
- 集成到 CI/CD
- 接入监控告警

**输出**：
- 评估平台（dashboard）
- 自动化脚本
- 告警规则

### 6.4 第四步：人工验证

**关键动作**：
- 自动化结果 + 人工抽检
- 定期校准评估标准
- 收集用户反馈

**输出**：
- 人工评估报告
- 评估标准更新

### 6.5 第五步：持续迭代

**关键动作**：
- 业务变化 → 指标更新
- 模型升级 → 重新评估
- 定期复盘
- 评估平台优化

**输出**：
- 持续迭代的评估体系
- 评估报告（定期输出）

## 九、评估的常见坑

### 9.1 评估集不能反映真实分布

**症状**：
- 评估集上效果 95%
- 线上效果只有 60%

**原因**：
- 评估集是精心构造的、过于"理想"
- 没有覆盖真实业务场景

**解决**：
- 使用线上数据采样
- 持续更新评估集
- 增加边界场景、异常场景

### 9.2 评估指标脱离业务

**症状**：
- 技术指标很好（准确率 95%）
- 业务指标很差（转化率没提升）

**原因**：
- 技术指标和业务指标脱节
- 没找到真正业务相关的指标

**解决**：
- 与业务方共同定义指标
- 用 A/B 测试验证
- 持续校准指标

### 9.3 评估结果不能解释

**症状**：
- 评估分数下降了
- 但不知道为什么

**解决**：
- 增加 case 分析
- 可视化（错误案例、可视化）
- 错误分类（哪些类型错误）

### 9.4 评估体系维护成本高

**症状**：
- 评估体系成了负担
- 团队抗拒做评估

**解决**：
- 自动化、工具化
- 集成到 CI/CD
- 简化评估流程

### 9.5 评估 ≠ 业务结果

**症状**：
- 评估分数高
- 但客户不满意

**原因**：
- 评估指标与客户体验脱节
- 客户体验还受其他因素影响（界面、响应时间）

**解决**：
- 持续收集用户反馈
- 关注整体体验
- 不只看评估分数

## 十二、实战代码示例（FDE 直接可用）

### 12.1 DeepEval 实战（单元测试风格）

> DeepEval 像 pytest 一样写评估用例，**FDE 首选的回归测试框架**

#### 12.1.1 安装与初始化

```bash
pip install deepeval
deepeval login --api-key=<your-key>
```

#### 12.1.2 第一个评估用例

```python
# test_rag_quality.py
from deepeval import assert_test
from deepeval.test_case import LLMTestCase
from deepeval.metrics import (
    AnswerRelevancyMetric,
    FaithfulnessMetric,
    ContextualRecallMetric,
    ContextualPrecisionMetric,
    HallucinationMetric,
)

# 你的 RAG 系统
def rag_query(question: str) -> dict:
    """返回 {answer, context, ground_truth}"""
    # 实际项目中调用你的 RAG 系统
    from my_rag import query
    return query(question)


# 评估指标
answer_relevancy = AnswerRelevancyMetric(threshold=0.7, model="gpt-4o")
faithfulness = FaithfulnessMetric(threshold=0.8, model="gpt-4o")
hallucination = HallucinationMetric(threshold=0.2, model="gpt-4o")


def test_answer_relevancy():
    """测试答案相关性"""
    result = rag_query("公司的年假政策是什么？")
    test_case = LLMTestCase(
        input="公司的年假政策是什么？",
        actual_output=result["answer"],
        expected_output="员工每年享有 10 天年假",  # 期望答案
        retrieval_context=[result["context"]],
    )
    assert_test(test_case, [answer_relevancy])


def test_no_hallucination():
    """测试无幻觉"""
    result = rag_query("公司 CEO 是谁？")
    test_case = LLMTestCase(
        input="公司 CEO 是谁？",
        actual_output=result["answer"],
        context=[result["context"]],
    )
    assert_test(test_case, [hallucination, faithfulness])


# 运行：deepeval test run test_rag_quality.py
```

#### 12.1.3 自定义评估指标

```python
from deepeval.metrics import GEval
from deepeval.test_case import LLMTestCaseParams

# 自定义：业务术语准确率
business_term_accuracy = GEval(
    name="Business Term Accuracy",
    criteria="""
    评估答案中业务术语使用是否准确：
    1. 专业词汇是否正确
    2. 是否误用同义词
    3. 是否对术语理解有偏差
    """,
    evaluation_params=[
```

### 12.4 LLM-as-Judge 实战（自定义评估）

#### 12.4.1 基础 LLM-as-Judge

```python
from langchain.chat_models import ChatOpenAI
from langchain.prompts import ChatPromptTemplate


class LLMJudge:
    """用 LLM 评估答案质量"""

    def __init__(self, model: str = "gpt-4o"):
        self.llm = ChatOpenAI(model=model, temperature=0)
        self.prompt = ChatPromptTemplate.from_messages([
            ("system", "你是一个严格的评估专家，根据标准给出 0-1 的分数。"),
            ("user", """
## 评估标准
{criteria}

## 问题
{question}

## 标准答案
{expected}

## 实际答案
{actual}

请按以下格式输出：
- 分数：0.X
- 理由：xxx
- 改进建议：xxx
            """),
        ])

    def score(self, question: str, expected: str, actual: str, criteria: str) -> dict:
        response = self.llm.invoke(self.prompt.format_messages(
            criteria=criteria,
            question=question,
            expected=expected,
            actual=actual,
        ))

        # 解析分数
        content = response.content
        score = 0.0
        for line in content.split("\n"):
            if "分数" in line:
                try:
                    score = float(line.split("：")[-1].strip())
                except:
                    pass

        return {"score": score, "reasoning": content}


# 使用

result = judge.score(
    question="公司的年假政策？",
    expected="员工每年 10 天年假",
    actual="公司每年提供 10 天的年假",
    criteria="答案是否准确、完整、与标准答案一致"
)
print(result)
# {'score': 0.9, 'reasoning': '...'}
```

```python
class MultiDimJudge:
    """多维度评估"""

    def __init__(self):
        self.judge = LLMJudge()

    def evaluate(self, question, expected, actual) -> dict:
        dimensions = {
            "准确性": "答案与标准答案的事实一致性",
            "完整性": "答案是否覆盖标准答案的所有要点",
            "清晰度": "答案表达是否清晰、无歧义",
            "专业性": "答案是否使用专业、准确的术语",
            "格式": "答案格式是否符合要求",
        }

        results = {}
        for dim, criteria in dimensions.items():
            result = self.judge.score(question, expected, actual, criteria)
            results[dim] = result["score"]

        # 综合分
        results["综合分"] = sum(results.values()) / len(results)
        return results
```

```python
# SelfCheckGPT 多次采样
def self_check(generate_fn, question: str, n: int = 5, threshold: float = 0.7) -> dict:
    """多次采样，检测一致性"""
    samples = [generate_fn(question) for _ in range(n)]

    # 用 LLM 评估一致性
    from sklearn.metrics.pairwise import cosine_similarity
    from langchain.embeddings import OpenAIEmbeddings

    embeddings = OpenAIEmbeddings()
    vectors = embeddings.embed_documents(samples)

    # 计算平均相似度
    sim_matrix = cosine_similarity(vectors)
    avg_sim = (sim_matrix.sum() - n) / (n * (n - 1))

    return {
        "samples": samples,
        "consistency": avg_sim,
        "is_consistent": avg_sim >= threshold,
    }
```

### 12.6 在线评估（A/B 测试）实战

```python
# A/B 测试框架
import hashlib
from datetime import datetime


class ABTestRouter:
    """简单的 A/B 测试路由器"""

    def __init__(self, experiments: dict):
        """
        experiments = {
            "model_v1_vs_v2": {
                "variants": ["v1", "v2"],
                "traffic_split": [0.5, 0.5],
                "metrics": ["accuracy", "latency", "cost"],
            }
        }
        """
        self.experiments = experiments

    def assign_variant(self, user_id: str, experiment_name: str) -> str:
        """分配用户到实验组"""
        exp = self.experiments[experiment_name]
        variants = exp["variants"]
        splits = exp["traffic_split"]

        # 用 user_id 哈希，保证同一用户始终在同一组
        h = int(hashlib.md5(f"{user_id}_{experiment_name}".encode()).hexdigest(), 16)
        ratio = (h % 1000) / 1000.0

        cumulative = 0
        for variant, split in zip(variants, splits):
            cumulative += split
            if ratio < cumulative:
                return variant

        return variants[-1]

    def record_metric(self, user_id: str, experiment_name: str, metric: str, value: float):
        """记录指标"""
        variant = self.assign_variant(user_id, experiment_name)
        # 实际项目中写入数据库 / 监控平台
        print(f"[{datetime.now()}] user={user_id} exp={experiment_name} variant={variant} {metric}={value}")


# 使用
router = ABTestRouter({
    "model_v1_vs_v2": {
        "variants": ["v1", "v2"],
        "traffic_split": [0.5, 0.5],
        "metrics": ["accuracy", "latency", "cost"],
    }
})

# 用户请求

    response = call_v1_model(question)
```

```python
# eval_platform/core/runner.py
from typing import List, Dict, Any
from datetime import datetime
import json
from pathlib import Path


class EvalRunner:
    """评估执行器"""

    def __init__(self, name: str, dataset_path: str, output_dir: str = "reports/"):
        self.name = name
        self.dataset_path = dataset_path
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(parents=True, exist_ok=True)

    def load_dataset(self) -> List[Dict]:
        with open(self.dataset_path, "r", encoding="utf-8") as f:
            return [json.loads(line) for line in f]

    def run(self, target_fn, metrics: List) -> Dict[str, Any]:
        """执行评估"""
        dataset = self.load_dataset()
        results = []

        for case in dataset:
            # 调用目标系统
            output = target_fn(case["question"])

            # 计算所有指标
            metric_results = {}
            for metric in metrics:
                score = metric.score(
                    question=case["question"],
                    expected=case.get("expected_answer"),
                    actual=output["answer"],
                    context=output.get("context", ""),
                )
                metric_results[metric.name] = score

            results.append({
                "question": case["question"],
                "output": output["answer"],
                "metrics": metric_results,
            })

        # 汇总
        summary = self._aggregate(results)

        # 保存报告
        timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
        report_path = self.output_dir / f"{self.name}_{timestamp}.json"
        with open(report_path, "w", encoding="utf-8") as f:
            json.dump({
                "name": self.name,
                "timestamp": timestamp,
                "total_cases": len(dataset),
                "summary": summary,
                "details": results,
            }, f, ensure_ascii=False, indent=2)

        return summary

    def _aggregate(self, results: List[Dict]) -> Dict:
        """汇总结果"""
        if not results:
            return {}

        all_metrics = results[0]["metrics"].keys()
        summary = {}
        for metric in all_metrics:
            scores = [r["metrics"][metric] for r in results]
            summary[metric] = {
                "mean": sum(scores) / len(scores),
                "max": max(scores),
                "min": min(scores),
                "median": sorted(scores)[len(scores) // 2],
            }
        return summary


# 使用

from eval_platform.metrics import Accuracy, Hallucination, Latency, Cost

summary = runner.run(
    target_fn=query,
    metrics=[Accuracy(), Hallucination(), Latency(), Cost()],
)
```

```python
import json
import sys
from pathlib import Path

# 质量阈值
THRESHOLDS = {
    "accuracy": 0.85,
    "hallucination_rate": 0.10,
    "avg_latency": 3.0,        # 秒
    "cost_per_query": 0.05,     # 元
}


def main():
    reports = sorted(Path("reports/").glob("*.json"), reverse=True)
    if not reports:
        print("❌ 无评估报告")
        sys.exit(1)

    latest = json.loads(reports[0].read_text(encoding="utf-8"))
    summary = latest["summary"]

    failed = []
    for metric, threshold in THRESHOLDS.items():
        if metric not in summary:
            print(f"⚠️  缺少指标：{metric}")
            continue

        actual = summary[metric]["mean"]
        if metric == "hallucination_rate":
            # 幻觉率越低越好
            if actual > threshold:
                failed.append(f"{metric}={actual:.3f} (阈值 {threshold})")
        else:
            # 其他指标越高越好
            if actual < threshold:
                failed.append(f"{metric}={actual:.3f} (阈值 {threshold})")

    if failed:
        print("❌ 质量门禁未通过：")
        for f in failed:
            print(f"  - {f}")
        sys.exit(1)

    print("✅ 质量门禁通过")


if __name__ == "__main__":
    main()
```

## 十五、评估工程常见问题 FAQ

### 15.1 评估集应该多大？

| 阶段 | 建议规模 |
|------|---------|
| POC | 50-100 |
| 上线 | 200-500 |
| 运维 | 500-2000 |
| 持续 | 2000+（持续更新） |

**原则**：
- POC 阶段可少，但必须覆盖核心场景
- 上线前必须有 200+ 评估集
- 持续运营时，评估集**只增不减**

### 15.2 评估频率如何定？

| 场景 | 频率 |
|------|------|
| 模型升级 | 每次升级必评估 |
| Prompt 优化 | 每次优化必评估 |
| 日常监控 | 实时 / 每日 |
| 业务报告 | 每周 / 每月 |
| 重大版本 | 完整评估 |

### 15.3 人工评估 vs 自动化评估？

| 维度 | 自动化 | 人工 |
|------|--------|------|
| 速度 | ⚡⚡⚡ | ⚡ |
| 成本 | 💰 | 💰💰💰 |
| 准确 | 中 | 高 |
| 规模 | 大 | 小 |
| 适用 | 回归测试 | 复杂场景 |

**最佳实践**：
- 90% 自动化 + 10% 人工
- 自动化覆盖常规场景
- 人工覆盖复杂场景、边界场景

### 15.4 评估指标冲突怎么办？

**典型冲突**：
- 准确率 ↑ vs 延迟 ↑
- 幻觉率 ↓ vs 召回率 ↓
- 成本 ↓ vs 效果 ↑

**解决思路**：
- 与业务方对齐优先级
- 用综合分（加权）评估
- 不同场景用不同指标
- 定期复盘调整权重

### 15.5 评估结果不可复现？

**原因**：
- LLM 温度非 0
- 数据采样随机
- 评估集未固定

**解决**：
- 评估时设 `temperature=0`
- 固定评估集（不变）
- 固定评估脚本版本
- 记录随机种子

### 15.6 评估体系维护成本高？

**解法**：
- 自动化、工具化
- 集成到 CI/CD
- 简化评估流程
- 团队共建
